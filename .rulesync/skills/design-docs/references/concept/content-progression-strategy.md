# 内容推进策略

用于把已经由 `DEC-*` 确认的推进形式、主轴和取舍落入概念案。推进形式仍有候选时停止落档并交 `design-inference`；缺少竞品、内容消耗、制作成本或实现事实时交 `design-evidence`。本模块只引用结论与证据，不重新选择或调查。

## 落档顺序

1. 核对上游
   - 必须有用户确认或 `DEC-*`，涉及外部、试玩或实现事实时必须引用 `EVID-*`。
   - 上游没有确认推进形式、主轴或排除边界时，不用通用经验替项目拍板。

2. 记录阶段单位
   - 阶段可以是一关、一区域、一次任务、一次 Run、一章剧情、一个赛季或一个能力层级。
   - 阶段单位必须能被玩家感知，并能被后续系统、内容与语义反馈共同表达。

3. 记录已确认推进形式

| 推进形式 | 已确认适用边界 | 已知风险 | 依据引用 |
|----------|----------------|----------|----------|
| 关卡制 | 有明确开始、结束、评分或通关条件 | 内容消耗快、后期铺量压力高 | 单关时长、关卡数量、复玩理由 |
| 解锁制 | 探索、收集、建造、经营、区域扩展 | 门槛不透明、玩家被迫刷资源 | 解锁条件、进度反馈、替代目标 |
| 无尽制 | 高分挑战、Roguelike、随机生成、对局循环 | 变化不足会快速疲劳 | 变化来源、难度递增、失败后回流 |
| 混合制 | 主线、支线、挑战、长线活动并存 | 范围膨胀、多个推进轴互相抢目标 | 主轴 / 副轴关系、阶段切片、优先级 |

4. 摘录决策依据
   - 只记录 `DEC-*` 已确认的采用依据、主推进轴和排除边界，不在概念案重做比较。
   - `DEC-*` 没有明确的非选方案不自行补写；确需比较时回 `design-inference`。
   - 混合制只落档已确认的主轴 / 副轴关系，避免每个系统都自称主线。

5. 定义推进承诺

| 参数 | 设计问题 |
|------|----------|
| 新内容解锁间隔 | 玩家多久能看到新目标、新规则、新空间或新组合？ |
| 单个内容消耗时长 | 一个关卡、区域、任务、Run 或活动能支撑多久？ |
| 总内容量 | 主线、全收集、赛季或长期目标需要多少内容？ |
| 复用深度 | 旧内容是否因高分、掉落、路线、构筑、难度或随机变化值得重玩？ |
| 制作成本 | 内容是否依赖手工铺量，还是能被规则、模块或系统变化支撑？ |
| 会话边界 | 解锁、失败、胜利、结算或休息点是否匹配玩家单次时长？ |

## 内容门控

门控应把玩家带回有趣的核心循环，而不是把玩家挡在等待、刷取或不透明条件前。

| 门控类型 | 使用条件 | 常见风险 |
|----------|----------|----------|
| 能力门控 | 新能力改变可达空间、解法或战斗方式 | 能力只像钥匙，不改变玩法 |
| 资源门控 | 资源积累本身有选择、取舍或风险 | 变成重复刷取 |
| 收集门控 | 收集过程有探索、路线或表达价值 | 清单化、查漏补缺无趣 |
| 时间门控 | 服务真实节奏、运营节奏或异步系统 | 等待被伪装成内容 |
| 技巧门控 | 玩家能力成长是核心乐趣 | 教学不足、失败归因不清 |
| 剧情 / 任务门控 | 叙事或任务链需要顺序铺陈 | 强制跑腿、主目标被打断 |

门控检查：
- 玩家能看见目标、当前差距、下一步行动和预计回报。
- 门控失败后仍有可做的有意义目标，而不是只剩重复劳动。
- 门控条件能被 UI、任务、关卡或环境线索清楚表达。
- 对目标玩家而言，门控是“差一点就到”，不是“不知道还差什么”。
- 高风险门控需要跳过、替代路径、重试、辅助或回退方案。

## 内容复用方式

内容复用必须提供新的选择、技巧、信息、风险或奖励，不应只是要求玩家重复同一件事。

- 成绩复用：星级、排行榜、计时、无伤、连击。
- 构筑复用：不同角色、技能、装备或路线改变解法。
- 掉落复用：稀有掉落、材料、收藏，但要控制疲劳和保底。
- 规则复用：词缀、随机事件、每日挑战、难度模式。
- 空间复用：新能力打开旧区域的新路径或新目标。
- 社交复用：合作、竞争、UGC、分享和异步挑战。
- 叙事复用：旧地点随阶段变化，提供新的世界状态或角色信息。

## 长线内容策略

- 一次性内容：主线、章节、关卡、剧情，优势是清晰，风险是消耗快。
- 系统性内容：构筑、随机、对抗、经营、创造，优势是复用高，风险是规则深度要求高。
- 周期性内容：赛季、活动、每日 / 每周目标，必须避免把登录压力当成乐趣。
- 扩展内容：DLC、资料片、关卡包，需提前判断题材、画风、系统和存档是否可扩展。
- 玩家生成内容：UGC、关卡编辑、MOD，需评估工具成本、审核、发现和质量波动。

## 推荐输出字段

- 阶段单位：玩家从什么阶段推进到什么阶段。
- 决策引用：用户确认或 `DEC-*`，以及相关 `EVID-*`。
- 已确认推进形式：关卡制 / 解锁制 / 无尽制 / 混合制。
- 采用依据：只摘录已确认的目标玩家、单次时长、核心循环、内容预算和商业模式约束。
- 排除边界：只记录 `DEC-*` 已明确暂不采用的推进形式及原因。
- 推进节奏：解锁间隔、单内容消耗时长、总内容量、复用深度和会话边界。
- 内容门控：门控类型、条件、进度反馈、失败恢复和替代路径。
- 内容复用：旧内容为什么值得回访，复用是否带来新选择或新技巧。
- 长线策略：主线内容、系统性复用、周期更新、DLC / 资料片或 UGC 边界。

## 质量检查

- 内容量和制作压力是否有项目约束或 `EVID-*` 支撑；缺失时是否已交 `design-evidence`。
- 推进形式、主轴和排除边界是否来自用户确认或 `DEC-*`，而非本模块重新比较。
- 推进形式是否匹配目标玩家单次时长、平台和核心循环。
- 门控是否让玩家理解差距和下一步行动。
- 旧内容复用是否提供新的决策、技巧、信息或奖励。
- 混合推进是否有明确主轴，避免所有推进线都被描述为同等核心。
- 长线内容是否与商业模式、题材扩展、画风制作成本和资源计划一致。
- 需要由 `design-docs:system` 进一步确认的最小推进切片是否已列为交接问题。
