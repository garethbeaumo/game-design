# 体验节奏与学习流程

用于在功能规则中定义教学、挑战、强度变化、首次体验和会话边界。它只写目标行为、内容块、规则变化与预设观察信号；实际完成率、用时、样本、试玩记录和归因属于 `design-evidence:playtest`。

## 玩家阶段

| 阶段 | 目标状态 | 规则要求 | 常见风险 |
|------|----------|----------|----------|
| 入门 | 理解目标与第一次输入 | 低门槛、即时反馈、可恢复失败 | 信息过量、目标不明 |
| 练习 | 主动学习规则 | 安全试错、逐步增加变化 | 难度断档、重复疲劳 |
| 熟练 | 稳定使用核心规则 | 组合、效率与风险取舍 | 唯一最优、纯重复 |
| 深度 | 优化或自我表达 | 高阶目标和可选限制 | 只靠数值门槛 |

## 节奏结构

- 每个内容块只引入少量新信息，并说明完成后的反馈和下一步。
- 高压段后提供低压、整理、奖励或明确结束点。
- 加载、过场、地图或提示只有在承接新目标、新规则或新状态时才占用注意力。
- 会话边界和预计时长必须来自已确认的目标玩家与产品约束，不使用通用经验值替代证据。
- 难度变化写规则与行为，不扩成独立数值曲线或参数表。

## 首次体验漏斗

首次体验可定义以下规则节点：

1. 首次进入：玩家应知道当前目标与第一步。
2. 第一次输入：低风险、反馈明确，能暴露输入理解问题。
3. 第一次成功：说明做对后的结果与下一步。
4. 第一次失败：说明原因、恢复与重试方式。
5. 第一次奖励：说明用途，不先给资源再让玩家猜价值。
6. 首次循环完成：目标、行动、反馈与推进形成最小闭环。
7. 教学退场：提示减少后仍可独立继续，并保留可选帮助。

## 预设观察信号

功能案只预先声明要观察什么：目标理解、首次输入、第一次成功、失败恢复、循环完成、提示退场后独立行动。测试执行后必须转 `design-evidence:playtest` 固化录像、日志、样本、指标和归因。

| | | 入门 / 练习 / 熟练 / 深度 | 升压 / 高压 / 释放 / 整理 | | |

## 首次体验
| 节点 | 目标行为 | 必要 Sign / Feedback | 失败保护 | 预设观察信号 |

需要判断实际问题出在哪里时转 `design-evidence:playtest`；需要比较多个节奏或教学方案时转 `design-inference`。
