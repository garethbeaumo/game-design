# 竞品拆解与可比性方法

用于把竞品观察转成可用于后续决策与正式设计的证据；本文件只判断可比性和迁移前提，不决定项目是否采纳。

## 竞品类型

| 类型 | 用途 | 风险 |
|------|------|------|
| 同品类竞品 | 验证玩家预期、核心循环、内容量和商业模式 | 容易照搬表层功能 |
| 相邻品类参考 | 借鉴某个机制、节奏或表现方式 | 需求可能不匹配 |
| 视觉 / 题材参考 | 锚定画风、世界观、商店第一印象 | 不能证明玩法成立 |
| 反例 | 识别应规避点、流失点和负面反馈 | 需要区分执行差和方向错 |
| 规模锚点 | 限制内容体量、系统深度和制作范围 | 不能选远超团队能力的对象 |

## 核心拆解问题

| 维度 | 必答问题 |
|------|----------|
| 玩家 | 它服务哪类玩家，玩家为什么首次进入、继续玩、回来 |
| 循环 | 玩家反复做哪些动词，短 / 中 / 长循环如何闭合 |
| 驱动力 | 发现、表达、积累、博弈、社交、技能中哪个是主驱动力 |
| 需求 | 具体满足了什么需求：爽感、掌控、成长、收集、表达、社交、挑战或放松 |
| 前提 | 它依赖什么：内容量、社交密度、随机性、操作手感、题材认知、付费模型 |
| 风险 | 哪些点会造成疲劳、P2W、门槛、挫败、内容枯竭或制作爆炸 |

## 有趣点提取

不要写“系统好玩”“画风好看”。写可观察设计点：

| 模糊说法 | 改写为可观察设计点 |
|----------|--------------------|
| 成长感强 | 每局结束展示 3 个可立即提升的目标，并让下一局能验证收益 |
| 探索好玩 | 地图上每 2 到 3 分钟出现一个可见但暂时到不了的目标 |
| UI 清楚 | 可操作对象用边框、动效和禁用态同时表达可用性 |
| 抽卡刺激 | 稀有结果有前置期待、揭示节奏、保底反馈和重复转化 |

## 可比性分类

| 分类 | 定义 | 证据输出 |
|------|------|----------|
| 高可比 | 目标玩家、平台、循环和前提基本一致 | 说明仍需验证的边界 |
| 条件可比 | 需求相似，但平台、体量、商业模式或系统结构不同 | 说明迁移必须改变的前提 |
| 反向信号 | 竞品问题可能支持相反方向 | 记录问题证据，不直接形成反向方案 |
| 不可比 | 需求、前提或成本明显不匹配 | 记录不可比原因，防止误用 |

## 常见误用

- 把竞品当作权威源：“竞品这么做”不是理由，玩家需求匹配才是理由。
- 只看功能，不看循环：同样的卡牌、装备、地图，在不同循环里含义完全不同。
- 只借成功点，不看前提：竞品能靠内容量撑住，本项目未必能。
- 只找相似，不找差异：差异化不清时，参考会变成无边界照搬。
- 用视觉参考证明玩法：画风对标只能证明感知方向，不能证明核心循环成立。
