# `competitor` 模式：竞品与品类证据

用于调查具体已上线游戏、版本、平台、品类惯例、内容体量和市场事实。产物是可追溯的竞品证据，不是本项目的借鉴结论。

## 权限

- 写入 `COMP-*` / `EVID-*`：对象、版本、平台、来源、日期、可观察设计、目标需求、成立前提、规模锚点、可比性和局限。
- 项目概念、目标玩家、团队规模和商业模式只用于选择比较维度。
- “采用 / 变体采用 / 反向采用 / 不采用”属于 `design-inference`，本模式不得提前作答。

## 工作原则

- 只把具体对象和可核对来源当作事实；概括性品类判断标为综合推断。
- 不做功能数量竞赛，重点记录玩家反复做什么、满足什么需求，以及依赖哪些内容、平台和商业前提。
- 需要最新销量、评价、在线人数、版本或市场数据时核对可靠来源，并标注数据日期。
- 同题材、同平台或热门不能自动证明可迁移。

## 按需读取

- 需要需求匹配、竞品类型、循环对比或规模表时，读取 `comparative-design-method.md`。
- 品类、产品形态、题材、画风或商店第一印象只作为调查维度；记录可核对事实与来源，不加载推论或正式设计 reference 来代写结论。

## 流程

1. 登记竞品名称、版本、平台、日期、来源、可靠性和选择理由。
2. 用动词链拆出短、中、长循环，并记录可观察规则、内容结构和反馈方式。
3. 说明设计点服务的玩家需求及其操作、内容、社交、随机性或商业前提。
4. 比较目标玩家、平台、产品形态、会话时长、内容量和团队能力，标出不可比维度。
5. 只在存在可核对依据时记录规模锚点；估算必须标为估算。
6. 输出事实、推断、局限和待决策问题，把采纳判断交给 `design-inference`。

## `standard` 输出

1. 调查问题、对象、版本 / 平台、日期与来源。
2. `COMP-*` / `EVID-*` 表：可观察设计、玩家需求、成立前提、可靠性。
3. 可比与不可比条件。
4. 规模锚点及证据局限。
5. 需要后续决策的问题，不预写答案。

循环矩阵、多竞品表、市场数据和规模表只在真正命中时展开。

## 自检

- 关键事实是否都有对象、版本、日期和来源。
- 是否区分观察、推断和未知。
- 是否说明设计成立的玩家需求和前提。
- 是否误写了本项目的方向、范围或规则。
