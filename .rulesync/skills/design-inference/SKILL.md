# 游戏设计推论与方案收束

在修改正式设计前，把问题、约束、证据、候选、取舍和致命假设推清楚。

## 权限边界

- **可写权威**：假设、候选方案、方案比较、`DEC-*`、反选代价、复查条件、决策依赖的证据缺口及其假设影响，以及验证致命假设的 Prototype 计划。证据本身的强度与状态只引用 `EVID-*`，不得改写；是否通过阶段门槛由 `design-workflow` 判定并写入。
- **只读输入**：`EVID-*`、现有概念 / 系统 / 功能设计、实现约束、平台与制作约束。
- **禁止越权**：不直接改写当前概念、`SYS-*`、P0-P3、产品 MVP、`RULE-*`、里程碑或实现架构；确认后的设计必须交 `design-docs` 落档。

## 使用原则

- 读取 `../design-workflow/references/artifact-output-profiles.md`；单一取舍默认用 `brief`。只有用户明确要求可归档的 `DEC-*`、正式决策记录或 Prototype 计划时才用 `standard`。
- 先明确决策问题和层级，再识别约束；先形成真实不同的候选，再收束。
- 区分硬约束、软约束和伪约束。当前实现、历史习惯、口头说法和竞品惯例默认不是硬约束。
- 玩家价值与学习点先于实现成本；成本只决定验证、缩小或延后方式。
- 高影响决策记录推荐结论、依据、放弃项、风险、验证信号和回退入口。
- 阻塞分支未确认时读取 `../design-workflow/references/grill-gate.md` 并使用 `grill-me`；不要把默认假设写成已确认决策。

## 上下文与 reference

只读取当前决策问题命中的 reference，不做全量预读。

1. 读取相关正式设计、最近 `DEC-*`、变更记录和现有 `EVID-*`。
2. 缺少具体竞品事实、测试归因或实现事实时，先使用 `design-evidence` 的对应模式；即使用户说“判断问题出在哪”，只要输入仍是原始试玩、反馈、指标或录像，就先固化证据。本 Skill 只引用证据 ID 并决定项目如何处理。
3. 约束与品类判断读取 `references/constraint-decision-matrix.md` 和 `references/genre-type-constraint-matrix.md`。
4. 发散方法读取 `references/ideation-breadth-methods.md`；循环和学习点诊断读取 `references/loop-driver-iteration-diagnostics.md`。
5. Prototype 读取 `references/prototype-validation-plan.md`；需要归档模板时读取 `references/phase-templates.md`。
6. 层级或落点不清时读取 `references/layer-boundaries.md`。

## 工作流程

1. **定义决策问题**
   - 当前必须决定什么，为什么现在决定。
   - 本次不回答什么，确认后应落到 `design-docs` 的哪个模式。

2. **建立约束与证据**
   - 标注约束类型、来源和证据状态。
   - 把“玩家会喜欢”“竞品这样做”“当前实现如此”等说法改写为可验证假设。
   - 缺少关键证据时，列出必要默认、对本次决策的影响及风险，不写阶段门槛状态。

3. **形成可区分候选**
   - 候选必须在玩家价值、学习点、体验、规则结构或验证成本上存在真实差异。
   - 通常保留至少两个可行候选；措辞变体不算独立方案。
   - 竞品和现有实现只能提供证据或启发，不能直接成为项目方案。

4. **比较并收束**
   - 比较有趣度、差异化、生命周期、顶层支持、证据强度和违反约束的风险。
   - 明确保留、延后与放弃项；实现成本只影响 Prototype、缩小验证或制作安排。
   - 形成 `DEC-*`：决策、依据、假设、放弃项、影响范围、验证信号和复查 / 回退条件。

5. **设计 Prototype**
   - 只验证不解决就无法继续的致命假设。
   - 写明原型类型、目标样本、观察证据、通过 / 失败标准和失败后的回退步骤。
   - Prototype 不是产品版本，不分配 P0-P3，也不定义产品 MVP。

6. **交正式设计落档**
   - 当前体验承诺与核心动作循环交 `design-docs` 的 `concept` 模式。
   - 系统边界、P0-P3、产品 MVP 与依赖交 `system` 模式。
   - 单系统行为、状态和事件交 `feature` 模式。
   - 本 Skill 只保存 `DEC-*` 与 Prototype，不复制正式设计正文。

## 输出契约

`standard` 只生成：

1. 决策问题、所属层级和正式落点。
2. 会改变选择的约束、证据、未知项和必要默认。
3. 可区分候选及关键差异。
4. 推荐结论、主要放弃项和反选代价。
5. `DEC-*` 决策记录。
6. 致命假设与最小 Prototype；没有时省略。
7. 风险、待确认和复查条件。

## 完成标准

- 决策问题与正式设计落点分开。
- 约束和事实都有来源与证据状态。
- 候选存在真实差异，并至少说明一个放弃项。
- `DEC-*` 包含依据、假设、反选代价、验证信号和复查条件。
- Prototype 没有膨胀成产品版本，正文没有越权写正式设计。
