# 策划产物输出档位

本文件只回答“本次交付多深、多大”。主责和权限查看 `routing-matrix.md`，目录与状态查看 `artifact-standards.md`。

## 通用规则

- 思考可以完整，正文只保留当前读者完成任务所需的信息。
- 一次请求默认只有一个主要产物；跨域内容列引用和后续落点。
- 输出结构是字段池，不是固定目录；未命中模块直接省略。
- 已有权威文档优先差量修订，不为套模板重写未受影响章节。
- 检查清单只用于内部自检，正文只呈现实际结论、风险和待确认项。

## 四档输出

| 档位 | 何时使用 | 交付边界 |
|------|----------|----------|
| `brief` | 咨询、事实核对、单一取舍、小改或局部差量 | 结论 / 差量、依据、影响、验收或下一步 |
| `standard` | 创建或修订一篇正式证据、决策、设计或治理产物 | 当前 Skill / 模式的核心骨架 + 命中的条件模块 |
| `implementation-ready` | 用户明确要求交实现 | 仅 `design-docs:feature` 在 `standard` 上补实现消费信息 |
| `full-package` | 用户明确要求跨概念、系统和功能的完整归档包 | `INDEX.md` + 模块化权威文件；禁止生成单文件 GDD 或正文汇编 |

用户未指定时，咨询默认 `brief`，明确创建或修订正式产物默认 `standard`。Skill 名称、问题复杂度、材料条数或参与人数都不能自动升级档位。

## `brief`

通常只输出：

1. 目标与结论。
2. 关键事实、取舍或 `原内容 → 新内容` 差量。
3. 真实影响与未知项。
4. 2～5 条可观察验收，或明确下一步。
5. 应落入的权威文档、模式或稳定 ID。

出现新的顶层方向、系统集合、状态机、三个以上系统影响，或八条验收仍无法覆盖时，升级为对应模式的 `standard`。

## `standard`

- 只定义当前 Skill / 模式拥有的权威；其他领域通过稳定 ID 引用。
- 只展开本次真正命中的条件模块，不附完整原始材料、候选全集或内部检查矩阵。
- 跨模式需求保留一个主要产物，其余写成后续同步任务。

## `implementation-ready`

- 只补当前功能切片真正消费的对象、状态、事件、字段语义、资源影响和验收。
- 复杂 Given / When / Then、存档兼容和 Unity 资源验证按需展开。
- 技术架构、类名和目录由实现方决定，除非它们是已确认外部约束。

## `full-package`

- 由 `design-workflow` 编排成独立子任务或后续任务；当前任务只处理一个模式并在结束时释放其上下文，不把完整包当作全量预读的例外。
- `INDEX.md` 只维护摘要、状态、依赖、开放问题和权威链接。
- 证据、决策、概念、系统、功能和治理产物分别维护。
- 即使用户要求“一次输出”，也只返回索引与模块文件清单，不拼接完整正文。

## 交付前自检

- 档位是否匹配用户用途，而不是匹配 Skill 的“重量”。
- 是否只有一个主要产物和一个可写权威。
- 是否省略空章节、未命中模块和重复背景。
- 是否把证据、决策或索引误当成正式规则源。
