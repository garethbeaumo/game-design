# 主动 Grill 门禁

策划相关 Skill 在关键定案前应主动使用 `grill-me`，把未拍板的高影响分支问清楚，而不是把模糊假设写进正式产物。

`grill-me` 是澄清手段，不拥有正式产物；完成后必须返回触发它的原 Skill。

## 何时使用

出现以下任一情况时先执行 `grill-me`：

1. 即将写入或锁定正式产物，但存在会改变方案的未确认分支。
2. 用户给出方向或“就这么定了”，但缺少反选代价或致命假设。
3. `design-inference` 已完成分析，仍有阻塞级选择需要用户确认。
4. 互斥方案会改变核心循环、产品 MVP、系统边界、玩家信任或关键依赖。
5. 用户要求压力测试、拷问设计、stress-test 或明确提到 grill。

高影响分支优先覆盖：

- 核心体验、玩家幻想与设计支柱。
- 主驱动力与核心循环动作。
- 目标玩家、非目标玩家与使用场景。
- Prototype / 产品 MVP 的必须做与明确不做。
- 商业模式、外部压力与玩家信任契约。
- 会改变系统边界或依赖的关键取舍。

## 何时不要使用

- `design-docs:feature` 可用 `brief` 处理的小改，且没有阻塞假设。
- 用户明确要求跳过追问、先按推荐默认推进。
- 问题能从代码库、现有文档或 `design-evidence` 直接回答。
- 纯路由咨询，且路线不依赖未确认设计决策。
- 同一会话里该分支刚被确认，没有新的冲突证据。

## 执行方式

1. 读取 `grill-me`，一次只推进一个决策树分支。
2. 先给推荐答案、理由和反选代价，再请用户确认或修正。
3. 能靠仓库、文档或证据回答的先自行查证。
4. 用户修正约束、驱动力或关键变体后，回原 Skill 的对应步骤重推。
5. 阻塞分支达成共享理解后，用简短确认摘要返回原 Skill，避免重复拷问。
6. 用户选择推荐默认时，标记为待验证并写明最晚确认时机。

## 与五入口的关系

| 场景 | 顺序 |
|------|------|
| 方向不清，需要方案比较 | `design-inference` → 必要时 `grill-me` → `design-docs` 落档 |
| 正式概念 / 系统 / 功能要定案 | `design-docs` 发现阻塞分支 → `grill-me` → 回原模式 |
| 只问流程或下一步 | `design-workflow`；仅当路线依赖未确认选择时插入 `grill-me` |
| 已有试玩或实现材料待解释 | `design-evidence` 固化证据 → `design-inference` → 必要时 `grill-me` |

## 完成标准

- 阻塞分支都有明确选择，或有带验证时机的显式默认。
- 每个已确认分支能复述选了什么、为什么和反选代价。
- 原 Skill 可以在不猜测关键前提的情况下继续产出。
