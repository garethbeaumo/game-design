# `concept`：概念约束

仅在目标玩家、体验承诺、核心循环或顶层边界实际变化时更新。概念是稀疏且可迭代的北极星约束，不是功能写入前必须完成的阶段。

## 可写范围

- 一句话概念与当前状态。
- 目标玩家、典型情境和核心体验承诺。
- 核心动作循环及其体验意义。
- 必须保持、明确不提供、不可牺牲或暂缓的顶层边界。
- 与本次变化直接相关的 `proposed` 假设；验证时机和回退条件仅在风险需要时补充。

只记录用户已经给出、当前权威已有或用户明确授权起草的结论。目标玩家、主题、动机或边界存在高影响互斥候选时交 `design-inference`；需要真实样本或外部事实时交 `design-evidence`。

## 差量字段

按本次变化选用字段，不要求每次补齐全部内容：

| 字段 | 记录内容 |
|------|----------|
| 当前性与来源 | `proposed / current / superseded`，以及直接采用或替代来源 |
| 验证性（按需） | 仅在命中验证问题时记录 `unverified / supported / rejected` 及证据引用 |
| 一句话概念 | 当前游戏是什么、玩家主要做什么 |
| 目标玩家与情境 | 优先服务谁、在什么条件下体验 |
| 体验承诺 | 玩家反复获得的核心感受或价值 |
| 核心动作循环 | 玩家动作、反馈与推进关系 |
| 顶层边界 | 必须保持、不提供、不可牺牲或暂缓的方向 |
| 验证与回退（按风险） | 待观察问题；已采用、高返工、不可逆或临近交付时再补信号、复查时机和恢复边界 |

初始 `proposed` 内容可以只包含本次有依据的字段。后续功能反向改变概念时，差量更新受影响字段并记录同步对象，不重写整份概念案。

## 按需读取

- 当前采用或明确提议的目标玩家、设备、能力或可访问性边界：`concept/target-player-context.md`
- 当前采用或明确提议的玩家动机和情绪承诺：`concept/player-motivation-emotion.md`
- 当前采用或明确提议的玩家信任与外部压力契约：`concept/player-trust-boundary.md`
- 当前采用或明确提议的主题、题材、表现与环境叙事约束：`concept/theme-mechanic-synergy.md`

这些 reference 只帮助落字段和检查一致性，不用于现场推导设计结论。

## 一致性与验收

- 本次改变是否与仍然有效的一句话概念、体验承诺、循环和边界冲突。
- `proposed / current / superseded` 是否可以清楚区分；验证相关时是否另记 `unverified / supported / rejected`。
- 被改变或删除的顶层约束是否列出真实受影响的系统或功能，而非要求补齐全局地图。
- 验收信号是否描述玩家可观察行为或体验，而不是把主观意图写成已经验证的事实。
- 是否误写了系统内部规则、实现架构、候选比较或证据结论。
