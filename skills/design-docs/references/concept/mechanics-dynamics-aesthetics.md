# 体验、玩家行为与系统动态映射

用于在概念层把目标体验、玩家行为、系统动态和验证信号串成可追踪链，回答“玩家为什么会产生这段体验”。本文件不定义对象、属性、状态、事件或具体规则；这些分别交 `design-docs:system` 和 `design-docs:feature`。

## 映射层级

| 层 | 回答什么 | 常见偏差 |
|----|----------|----------|
| 体验目标 | 玩家应感到什么、学到什么或反复追求什么 | 只写“爽”“沉浸”“策略” |
| 玩家行为 | 玩家实际会做什么、比较什么、争取什么或避免什么 | 跳过行为直接列功能 |
| 系统动态 | 行为与反馈组合后会形成什么循环或模式 | 没解释为什么愿意重复 |
| 验证信号 | 哪种可观察行为能说明体验正在发生 | 只写“后续测试” |

规则：

- 不能只从设想正推“应该会好玩”；要写可观察的目标行为。
- 同一体验可能由多种系统结构承载，概念层不提前选定内部规则。
- 如果目标行为与体验承诺相反，先回 `design-inference` 判断方向，不用文案掩盖。
- 副循环若诱发新的主行为，回概念层确认是否改变产品方向。

## 输出片段

```markdown
## 体验映射
| 体验目标 | 目标玩家行为 | 预期系统动态 | 可观察验证信号 | 下游落点 |
|----------|--------------|--------------|------------------|----------|
| | | | | SYS / RULE 待定义 |
```

需要创建 `SYS-*` 时转 `system`；需要定义触发、状态、事件、反馈或异常恢复时转 `feature`；需要分析实际试玩结果时转 `design-evidence:playtest`。
