# 目标玩家与使用场景

用于定义项目服务谁、玩家为什么进入、在什么环境中游玩，以及哪些人不是当前优先对象。目标是把“给谁玩”写成概念约束，而不是人口统计标签、完整用例流程或界面方案。

## 概念级字段

| 维度 | 需要回答 |
|------|----------|
| 玩家经验 | 新手、休闲、核心、竞技、收集、社交或创作等经验状态 |
| 核心目标 | 玩家进入游戏时想完成什么、证明什么或获得什么情绪 |
| 主动机 | 持续行动与重复游玩的主要原因 |
| 使用场景 | 平台、输入方式、单次时长、注意力与可打断环境 |
| 能力边界 | 学习、操作、感知、设备与环境限制 |
| 非目标玩家 | 本阶段明确不优先服务的人群及代价 |
| 确认来源 | 用户确认、`DEC-*` 或 `EVID-*` 引用 |

人口统计只能作辅助。描述必须能约束核心动作复杂度、信息密度、节奏和失败压力，但不能在本层展开菜单路径、控件状态或逐步交互。

## 使用原则

- 不把设计师本人或团队偏好当成目标玩家事实。
- 目标玩家过宽时，回 `design-inference` 收束互斥需求。
- 试玩、访谈和指标的事实与可信度由 `design-evidence` 维护；这里只引用证据 ID。
- 设备、操作或可访问性约束只写项目级承诺；具体输入与反馈落到 `design-docs:feature`。
