# 玩家能力、环境与可访问性约束

用于目标玩家能力差异、设备环境、注意力状态和可访问性会影响核心体验、功能规则、UI 输入或测试归因时。目标不是让每个设计服务所有玩家，而是把“谁能自然完成、谁会被排除、为什么可以接受”写成可验证约束。

## 基本原则

- 先确认目标玩家和核心挑战；不要把无意的看不清、听不清、点不到或记不住伪装成难度。
- 可访问性不是事后开关；它会影响目标尺寸、时间窗口、信息冗余、反馈通道、重试成本和验收标准。
- 允许声明非目标玩家，但必须写清排除原因、风险和是否需要替代路径。
- 同一规则要按设备和环境拆开看：PC、手柄、触屏、掌机、低亮度、嘈杂环境和可被打断场景不能共享同一假设。

## 约束维度

| 维度 | 需要确认 | 常见设计回应 |
|------|----------|--------------|
| 视觉 | 颜色区分、字号、对比度、遮挡、动效强度 | 形状 / 图标冗余、状态文字、对比度、减少闪烁、可缩放 UI |
| 听觉 | 关键反馈是否只靠音效或语音 | 字幕、视觉提示、震动、日志留存 |
| 运动控制 | 精确点击、连打、长按、拖拽、反应窗口 | 容错、缓冲输入、吸附、可调窗口、替代输入、取消路径 |
| 认知负担 | 记忆步骤、同时信息、抽象规则、选择数量 | 分步展示、外显状态、分组、推荐、练习任务 |
| 注意力与环境 | 碎片化、噪音、打断、低网速、低电量 | 可暂停、短循环、自动保存、断线恢复、关键信息留存 |
| 晕动与疲劳 | 镜头晃动、快速转向、连续高压操作 | 镜头选项、低压恢复段、节奏分块、疲劳监控 |

## 预设观察信号

这里只定义目标人群、场景和观察问题；实际测试、样本偏差与归因统一由 `design-evidence:playtest` 固化为 `EVID-*`。

- 目标设备和典型环境：停顿、误触、误读、遗漏、疲劳和放弃。
- 反馈冗余：静音、仅画面、低亮度、手柄、触屏和可被打断场景下是否仍能理解。
- 精确输入：命中率、误触率、用时、失败原因和主观疲劳；规格定义可读取 `../feature/input-precision-control.md`。
- 复杂流程：步骤遗漏、返回、重复点击、查找时间和能否复述下一步。
- 样本边界：替代样本与内部熟练玩家只能标为限制，不能直接升级为目标玩家证据。

## 红线

- 关键目标只靠颜色、音效、一次性动画或低可见度环境线索传达。
- 高频操作依赖过小目标、连续精确拖拽、过短时间窗口或无法取消的长按。
- 失败惩罚过重，但失败原因可能来自设备、环境、反馈不足或可访问性限制。
- 可访问性选项会破坏核心挑战却没有分级、模式或排行榜边界说明。
