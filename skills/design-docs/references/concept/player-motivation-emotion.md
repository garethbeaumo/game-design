# 玩家动机与情绪承诺字段

仅在当前概念已经采用某项玩家动机或情绪承诺，或用户明确要求把指定方向写成 `proposed` 提议时读取。本 reference 不使用动机分类替项目选方向，也不从通用心理学推导玩家需求。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 目标玩家 / 情境 | 该承诺适用于谁、在什么体验片段发生 |
| 动机陈述 | 玩家为什么愿意开始、继续或再次进入该循环 |
| 目标情绪 | 完成短循环或关键节点后希望留下的感受 |
| 情绪来源 | 哪个动作、反馈、风险、关系或成长结果兑现它 |
| 反向情绪 | 当前设计明确要限制的体验及允许边界 |
| 高光 / 低谷 | 应被感知的高光，以及失败、等待、落后时的恢复承诺 |
| 可观察验收 | 玩家行为、复述或反馈中应出现什么信号 |
| 复查与回退 | 何时检查，未兑现时回退或修改什么 |

只记录当前设计已经采用的 `current` 内容或明确授权起草的 `proposed` 内容。比较多种动机结构或情绪曲线且达到高影响或高返工升级门槛时交 `design-inference`；低成本可逆判断保持内联。真实行为、访谈和归因需专项调查时交 `design-evidence`。

## 一致性与验收

- 动机和情绪是否由可指认的玩家动作与系统反馈兑现，而不只依赖宣传词或美术气氛。
- 同一目标玩家的承诺是否与仍有效的核心循环、挑战强度和外部压力边界冲突。
- 反向情绪与低谷恢复是否有清楚边界，而不是承诺“永不失败”一类不可验收目标。
- 可观察信号是否仍是 `unverified` 要求，没有被写成 `supported` 或已发生的事实。
- 修改或删除承诺时，是否同步直接承载它的功能规则。
