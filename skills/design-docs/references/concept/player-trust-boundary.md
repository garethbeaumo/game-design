# 玩家信任与外部压力契约

用于记录现实时间、登录、体力、等待、社交义务、排行、赛季、付费、广告、概率奖励、永久损失或缺席惩罚等机制已经采用的玩家契约。只写 `current` 结论或明确授权的 `proposed` 提议，不在本 reference 内判断商业模式或参与策略应如何选择。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 机制与触发 | 什么机制在何时把压力带到游戏外部 |
| 服务的体验 | 它支持哪条 `current` 体验承诺或核心循环 |
| 玩家预知 | 玩家在行动前能看到的时间、概率、成本、损失与结果 |
| 参与边界 | 是否可选、可跳过、可替代，退出会发生什么 |
| 上限与保护 | 当前采用的次数、成本、损失、冷却、补偿或保护边界 |
| 恢复路径 | 错过、失败、断线、退出或误操作后如何恢复 |
| 可观察验收 | 玩家应能复述什么，系统应能记录什么结果 |
| 复查与回退 | 何时验证信任影响，失败时关闭或恢复哪条规则 |

若上述边界仍有多个高影响候选，交 `design-inference`；真实分层行为、访谈、付费或留存归因交 `design-evidence`。

## 一致性与验收

- 玩家在不可逆行动前是否能理解真实成本、概率、时间、损失和退出结果。
- 外部压力是否仍指向声明的核心体验，是否与“非目标体验”或目标玩家承诺冲突。
- 可选、替代、上限、保护和恢复字段是否互相一致，不产生文档内自相矛盾的契约。
- 验收是否覆盖理解、主动参与、退出和恢复，而非只把参与率上升当作体验已成立。
- 修改或删除机制时，是否同步玩家可见说明、相关规则和仍然存在的外部引用。
