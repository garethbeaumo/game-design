# 目标玩家与使用情境约束

仅在目标玩家、设备环境、能力差异或可访问性承诺已经由当前权威给出，或用户明确要求把它写成 `proposed` 提议时读取。本 reference 负责记录字段，不负责推导目标客群或替代用户研究。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 优先服务对象 | 与本次体验相关的行为、动机、经验或能力特征 |
| 非目标范围 | 当前明确不为哪些使用方式或需求优化 |
| 使用情境 | 会话、设备、输入、空间、注意力、联网或语言条件 |
| 能力边界 | 感知、操作、认知或语言条件如何影响核心循环 |
| 设计承诺 | 必须提供的替代、容错、反馈或帮助语义 |
| 验证与回退 | 待观察信号、复查时机和承诺不成立时的处理 |

只填写本次变化涉及的行。具体控件、页面和实现方案不属于概念约束；样本招募、可用性测试和真实玩家结论交 `design-evidence`。

## 一致性与验收

- 玩家标签是否落实为会改变设计的行为或使用条件，而不是只写宽泛人口属性。
- 使用情境、能力边界和设计承诺是否与当前核心循环及体验承诺一致。
- `proposed` 假设是否明确标记，是否没有把内部猜测或 `unverified` 内容写成 `supported` 的真实玩家事实。
- 验收是否能观察目标玩家在目标环境下完成、理解或恢复核心动作。
- 删除或收窄承诺时，是否列出直接受影响的功能规则和玩家反馈。
