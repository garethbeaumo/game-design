# 主题、机制与表现约束

仅在主题、题材、表现基调或环境叙事约束已经由当前设计采用，或用户明确要求把指定方向写成 `proposed` 提议时读取。本 reference 负责让结论可写、可检查，不负责从题材推导主题或为机制组合做方案比较。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 核心主题 | 玩家最终应感受到或理解的中心信息 |
| 题材与边界 | 当前承载主题的设定，以及明确不表达什么 |
| 玩家动作 | 哪些已存在的核心动作直接承载主题 |
| 机制反馈 | 成功、失败、奖励或惩罚应传达什么语义 |
| 表现约束 | 美术、音频、动画、镜头或 UI 必须保持的基调与禁区 |
| 环境叙事 | 当前采用的线索内容、载体、可见度和作用 |
| 关键信息载体 | 不能只靠低可见线索传达的目标或规则 |
| 可观察验收 | 玩家应能感知、复述或正确行动的内容 |
| 复查与回退 | 何时检查，冲突时优先恢复哪条约束 |

创造或比较主题、机制组合和表现方案且达到高影响或高返工升级门槛时交 `design-inference`；低成本可逆选择在当前变化中内联判断。需要专项试玩或受众证据时交 `design-evidence`。

## 一致性与验收

- 主题、玩家动作、机制反馈和表现约束是否传达相容语义。
- 环境叙事是否补充世界与氛围，而关键目标和核心规则仍有明确载体。
- `proposed` 表现方向是否保持 `proposed`，没有因被采用为 `current` 就误写成已完成资源或 `supported` 的真实玩家感知。
- 修改主题或表现边界时，是否只同步直接冲突的功能与资源语义。
- 验收是否能区分“内容已经放入”与“玩家确实感知并理解”。
