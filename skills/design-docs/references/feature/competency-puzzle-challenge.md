# 能力门槛与谜题挑战

用于设计谜题、关卡挑战、技能检查、能力门槛、提示系统和辅助机制。目标是让挑战公平、可学习、可验证，而不是让玩家靠猜规则、重复试错或设计师口头提示通关。

## 挑战分类

先判断挑战主要要求玩家具备什么能力。多数挑战是混合型，但必须知道主要失败原因。

| 类型 | 依赖 | 常见失败 | 设计处理 |
|------|------|----------|----------|
| 记忆型 | 路线、顺序、地图、敌人位置、模式识别 | 重复同一路径后无聊 | 增加可控变化、缩短重复段、保留核心规则一致 |
| 技能型 | 输入、反应、空间判断、计划、资源管理 | 能力不足导致挫败 | 提供练习、辅助、容错、提示或替代路径 |
| 知识型 | 理解规则、机关关系、系统组合 | 猜规则或漏信息 | 明确目标、可观察线索、先教后考 |
| 组合型 | 多机制同时使用 | 不知道先后顺序或组合可能性 | 分步教学、逐步叠加、保留回退空间 |

## 能力链

每个挑战都要说明玩家必须已经掌握哪些能力，在哪里学习，在哪里被验证。

| 字段 | 要求 |
|------|------|
| 前置能力 | 玩家进入挑战前必须会什么 |
| 教学位置 | 该能力第一次被安全展示或练习的位置 |
| 验证位置 | 玩家必须主动使用该能力才能通过的位置 |
| 组合方式 | 是否把多个已学能力组合成新问题 |
| 失败反馈 | 玩家失败时能否理解缺的是知识、输入、时机还是路线 |
| 辅助机制 | 卡住时如何提示、降低门槛或提供替代路径 |

## 谜题质量

- 目标清楚：玩家知道最终要达成什么状态。
- 规则清楚：玩家知道可操作对象、限制和反馈。
- 确定性：相同输入产生相同结果，随机性不破坏解法判断。
- 非蛮力：正确解法来自理解规则、观察线索或组合能力，不是枚举所有可能。
- 渐进提示：提示从方向性线索到具体行动逐步升级，避免第一步就给答案。
- 可恢复：失败后可以重试、撤销、重置机关或回到安全状态。

## 提示梯度

| 等级 | 内容 | 使用时机 |
|------|------|----------|
| 0 无提示 | 只给环境和规则反馈 | 玩家仍在正常探索 |
| 1 方向提示 | 提醒观察区域、目标或相关对象 | 玩家停滞但没有连续失败 |
| 2 关系提示 | 点出对象之间的因果关系 | 玩家重复错误或明显漏信息 |
| 3 操作提示 | 给出下一步动作或路径 | 玩家长期卡住、即将流失 |
| 4 跳过 / 辅助 | 降低输入要求、自动演示或替代路径 | 挑战不是当前版本核心验证目标 |

## 预设观察信号

功能规则只声明验证对象与问题；实际招募、独立试玩、访谈、记录和归因交 `design-evidence:playtest`。

- 未参与设计的目标玩家能否在无口头解释下独立尝试。
- 第一次理解目标、发现规则和成功组合能力所需的时间。
- 输入不足、观察遗漏、规则误解、路径记忆和资源不足等可区分失败信号。
- 玩家能否复述目标、规则、失败原因和下一步计划。
- 是否存在只有设计师知道的隐藏逻辑、视觉误导或不可恢复死局。
