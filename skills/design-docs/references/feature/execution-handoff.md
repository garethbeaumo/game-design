# 功能实现交接

仅在 `design-docs:feature` 使用 `implementation-ready` 档时读取。它把已确认 `RULE-*` 整理为实现可消费的行为契约，不替程序决定架构，也不重新分配 P0-P3、发布阶段、人员或里程碑。

## 使用原则

- 写清必须满足的行为、数据语义和可观察结果，不指定类名、目录或框架。
- 功能切片只引用上游 `SYS-*` 已有产品优先级；不得在交接表内重定义。
- 规则成立所必需的范围、单位和默认值可以内联；不扩写独立数值模型。
- UI 只记录玩家必须知道的事件、原因、结果和下一步；不创建页面、控件或导航方案。
- Unity 资源只写影响类型与验证点，实际修改仍遵守项目 Unity 规则。
- 制作排期、发布门槛与回退安排交 `design-workflow`；实际测试结果交 `design-evidence`。
