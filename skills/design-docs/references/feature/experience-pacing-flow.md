# 体验节奏与学习流程字段

仅在教学、挑战、提示、强度变化、首次体验或会话边界已经由当前规则采用，或用户明确要求把指定方向写成 `proposed` 提议时读取。本 reference 记录顺序和行为契约，不根据通用阶段模型替项目生成节奏方案。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 适用玩家 / 情境 | 该流程服务谁、何时进入、会话约束是什么 |
| 节点 / 内容块 | 当前规则实际存在的步骤或体验片段 |
| 进入条件 | 进入该节点前必须成立什么 |
| 目标行为 | 玩家在该节点需要理解或完成什么 |
| 新增信息 / 规则 | 本节点首次要求玩家处理什么变化 |
| 强度与时长约束 | 当前采用的压力、休整、时长或结束边界 |
| 反馈与帮助 | 玩家如何知道目标、结果和下一步 |
| 失败与恢复 | 失败、跳过、中断或重进后的行为 |
| 退出条件 | 如何完成、离开或进入下一节点 |
| 可观察验收 | 理解、完成、失败恢复和独立行动的信号 |

不要求每个功能都具备固定的新手漏斗或完整阶段。比较多种教学、挑战或节奏结构且达到高影响或高返工升级门槛时交 `design-inference`；低成本可逆判断保持内联。真实完成率、用时、录像、样本和归因需专项调查时交 `design-evidence`。

## 一致性与验收

- 节点顺序、进入 / 退出条件和规则变化是否闭合，是否存在无法到达或无法退出的节点。
- 同一节点的目标行为、反馈、失败原因和恢复路径是否相互支持。
- 时长和强度字段是否来自 `current` 设计约束或明确的 `proposed` 提议，而不是伪装成 `supported` 的通用经验结论。
- 验收是否覆盖本次实际改变的理解、完成、恢复或独立行动，不强制补测无关阶段。
- 修改或删除节点时，是否同步直接相连的前后节点、提示和恢复入口。
