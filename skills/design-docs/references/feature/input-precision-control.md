# 输入精度与操作目标规格

仅在瞄准、QTE、命中框、互动点、拖拽、投掷、蓄力、闪避、格挡、节奏点击或手柄焦点等操作规格已经采用，或用户明确要求把指定规格写成 `proposed` 提议时读取。本 reference 记录可实现、可验收参数，不根据通用经验替项目决定难度或容错。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 操作与情境 | 玩家在什么状态下完成什么操作 |
| 输入设备 / 平台 | 鼠标、键盘、手柄、触屏或当前采用的混合输入 |
| 起点与目标 | 光标、角色、准星、手指或焦点起点；目标形状与语义 |
| 尺寸与距离 | 命中框、互动区、屏幕占比、镜头或角色距离 |
| 运动与可见性 | 速度、方向变化、遮挡、闪烁或焦点变化 |
| 时间规格 | 输入窗口、缓冲、判定、冷却、后摇或取消窗口 |
| 容错 / 辅助 | 吸附、自动瞄准、扩展区域、预选焦点或辅助模式 |
| 结果与反馈 | 命中、擦边、过早、过晚、不可达和失败原因反馈 |
| 恢复与风险 | 重试、取消、误触保护、不可逆结果和疲劳边界 |
| 可观察验收 | 各目标平台要观察的命中、误触、用时、失败和疲劳信号 |

只填写本次规则真正需要的量纲；未采用数值保持 `proposed`，已采用但尚未验证的数值写 `current + unverified`，不伪造“最佳”或 `supported` 参数。比较不同输入、难度或辅助方案且达到高影响或高返工升级门槛时交 `design-inference`；低成本可逆判断保持内联。真实测试与归因需专项调查时交 `design-evidence`。

## 一致性与验收

- 规格是否标明适用平台和输入设备，单位、范围及边界取值是否可解释。
- 目标、时间窗口、容错、反馈和失败恢复是否描述同一操作语义。
- 高风险或不可逆结果是否具备当前规则已承诺的预知、取消或恢复入口。
- 验收是否能区分目标规格、输入延迟、镜头 / 遮挡、反馈和玩家策略等不同失败信号。
- 修改或删除规格时，是否同步直接依赖它的难度、反馈和辅助规则。
