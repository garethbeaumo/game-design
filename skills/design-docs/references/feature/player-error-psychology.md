# 玩家错误与失败保护

用于在功能规则中预先定义允许哪些失败、玩家必须看到什么、失败代价如何恢复，以及高风险选择需要哪些保护。它不分析实际试玩或反馈；录像、日志、玩家说法、样本与问题归因统一交 `design-evidence:playtest`。

## 错误类型

| 类型 | 规则问题 | 可选设计处理 |
|------|----------|--------------|
| 操作错误 | 输入窗口、目标尺寸、响应与目标玩家能力是否匹配 | 容错、辅助输入、明确反馈、低风险练习 |
| 流程错误 | 是否存在多余步骤、错误入口或无法返回 | 缩短路径、清楚入口、取消与恢复 |
| 遗漏错误 | 玩家是否可能漏掉关键动作或状态 | 前置信号、待办状态、轻量提醒 |
| 决策错误 | 玩家是否理解选项差异和失败代价 | 预览、确认、撤销、低成本试错 |
| 规则误解 | 玩家是否会沿用错误心智模型 | 对比反馈、示例、首次安全验证点 |

## 失败与风险规则

- 有趣挑战可以保留失败，但原因、结果和下一步必须可理解。
- 低风险路径不应被隐藏；高风险高回报必须提前暴露失败代价。
- 长期资源损失、不可逆选择或永久惩罚需要确认、预览、撤销、保险或补救中的至少一种。
- 学习型失败应低惩罚并快速重试；核心赌注可以更重，但必须保证输入可靠和规则可读。
- 规则必须写明检查点、重试、续关、取消、第二次机会或永久损失的具体语义。

## 预设验证信号

功能案可以预先声明需要观察的信号，但不能填写实际结果或归因：

- 玩家是否能说出失败原因与下一步。
- 失败后能否找到取消、重试或恢复路径。
- 高风险选择前是否理解代价与不可逆性。
- 新规则是否容易被旧经验、表现或默认项误导。

实际观察发生后，由 `design-evidence:playtest` 建立 `TEST-*` / `EVID-*`；若证据表明需要比较不同改法，再交 `design-inference`。
