# 策略互动与收益规则字段

仅在战斗、PVP、PVE 对抗、阵营、合作、交易、公共资源或克制关系已经采用互动结构，或用户明确要求把指定方向写成 `proposed` 提议时读取。本 reference 记录行动、收益、信息与反制契约，不负责诊断后替项目选择博弈结构。

## 按需字段

状态沿用 `design-docs` 入口的两维契约；下表只列本专题新增字段。

| 字段 | 记录内容 |
|------|----------|
| 行动者 / 情境 | 谁在什么局面中作出选择 |
| 可选行动 | 玩家实际可见、可执行的行动 |
| 对方 / 系统状态 | 会改变结果的其他行动或状态 |
| 个人结果 | 对行动者的资源、风险、位置、信息或胜负结果 |
| 共享结果 | 对队伍、阵营、市场、公共资源或世界状态的结果 |
| 可见信息 | 决策前、执行中和结算后分别能知道什么 |
| 成本与限制 | 资源、窗口、冷却、暴露、次数或资格边界 |
| 反制 / 协作 | 当前采用的反制、配合、退出或替代路径 |
| 结算与反馈 | 如何解释收益、损失、贡献、失败和责任 |
| 已知风险边界 | 当前已采用或已有证据记录的占优、合谋、搭便车、僵局或利用风险及限制 |
| 可观察验收 | 选择、反制、贡献、复盘和极端路径的验证信号 |

发现或比较占优策略、均衡、收益结构和克制方案且达到高影响或高返工升级门槛时交 `design-inference`；低成本可逆判断保持内联。真实玩家行为、比赛数据和归因需专项调查时交 `design-evidence`。

## 可选记录表

| 行动者 | 行动 | 对方 / 系统状态 | 个人结果 | 共享结果 | 可见信息 | 成本 / 限制 | 反制 / 协作 | 结算反馈 |
|--------|------|-----------------|----------|----------|----------|-------------|-------------|----------|
| | | | | | | | | |

只有当规则本身存在多方收益关系时才使用该表；单人线性流程不需要补成收益矩阵。

## 一致性与验收

- 同一行动在相同条件下的成本、结果和结算是否一致，冲突时是否有明确优先级。
- 行动所需信息、反制或协作入口是否在玩家需要决策时可获得。
- 个人结果、共享结果和贡献反馈是否使用相同责任边界。
- 已知利用风险及保护规则是否可触发、可观察、可回退，而不是把推测写成已证实问题。
- 修改或删除行动、收益或克制关系时，是否同步直接受影响的结算、反馈和外部消费者。
