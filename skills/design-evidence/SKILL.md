# 游戏设计证据

围绕一个会影响当前设计变更的证据问题，建立可复查的来源快照、事实层级与有限推断。默认交付最小充分证据，不为每次迭代制造完整研究报告。

## 启用门槛

先判断是否真的需要专项证据工作。满足任一条件才使用本 Skill：

- 多个来源、版本、样本或环境互相冲突，直接阅读不足以判断。
- 事实会改变高影响或跨系统选择，需要他人复查、复现或长期引用。
- 试玩、访谈、日志、指标或 A/B 原始材料需要样本、偏差或归因分析。
- 用户明确要求竞品调查、试玩归因、当前设计行为的实现审计、证据报告或复查已有结论。

普通功能增改已有用户确认、当前规则或直接实现定位时，在当前变更中写一行“依据 / 局限”即可，不创建 `EVID-*`，也不转入本 Skill。

## 模式

先读取 `references/evidence-model.md`，再按主要证据问题选择一个模式；混合材料可作为旁证，不必拆成多份报告。

| 模式 | 适用问题 | 必读 reference |
|------|----------|----------------|
| `competitor` | 具体竞品、品类、版本、平台、规模或市场事实 | `references/competitor.md` |
| `playtest` | 试玩、访谈、问卷、社区反馈、日志、指标或 A/B | `references/playtest.md` |
| `implementation` | 代码、场景、Prefab、配置、构建、部署或生产链路 | `references/implementation.md` |

## 记录粒度

- 默认输出一个证据切片：结论、关键事实、来源快照、可信度、局限和受影响问题。
- 只有证据需要独立生命周期时才创建 `EVID-*`：他人需要复现 / 审计、会被多次引用、来源存在实质冲突，或用户明确要一份独立证据交付。高影响或跨系统本身只提高调查强度，不自动建档。
- 子事实只有被代码、测试、任务或多个维护文档外部引用时才沿用项目现有稳定标识；普通观察不另造编号体系。
- 新一轮调查只记录新增、替换、失效的来源和被改变的结论，不重写未受影响的背景。

## 流程

1. 通过启用门槛，定义证据问题、当前基线、本次影响范围和停止条件。
2. 为来源建立快照，再提取可观察事实；缺少版本、样本或环境时明确标为未知。
3. 按证据层级整理事实、交叉印证、有限推断、反例与冲突。
4. 只做回答当前问题所需的最小验证；达到停止条件后结束调查。
5. 输出证据切片或必要的 `EVID-*`，说明哪些结论被本次来源差量改变。
6. 证据足够后交给本次问题的实际后续所有者：确有高影响真实取舍时交 `design-inference`；已确认规则需要落档时交 `design-docs`；若调查由活跃版本 change-set 发起并用于范围、门槛或发布判断，则把有限结论交回 `design-workflow`。不要为了凑固定链路绕经无权处理该结论的 Skill。

## 完成标准

- 关键事实能回到来源快照、版本、样本或环境。
- 直接观察、交叉印证、有限推断和未知项没有混写。
- 证明范围与结论范围一致，没有用静态检查冒充运行或生产 E2E 证明。
- 没有为了模板扩张调查，也没有偷偷完成方案取舍或改写正式设计。
