# `competitor`：竞品与品类证据

调查具体已上线游戏、版本、平台、品类惯例、内容体量或市场事实，回答一个会影响当前设计的问题，不替本项目决定是否采纳。

## 调查步骤

1. 用 `./evidence-model.md` 固定对象、版本、平台、地区、日期、来源与获取方式。
2. 优先直接游玩、官方版本说明和一手材料；攻略、商店页、视频或社区讨论标明二手边界。
3. 只提取与问题相关的可观察规则、玩家动词、反馈、循环和内容结构。
4. 说明设计点成立所依赖的目标玩家、会话、商业、社交、内容量和团队条件。
5. 比较可迁移条件与缺失条件；规模数字只有在来源可靠时登记，推算明确标为估算。

## 可比性镜头

| 维度 | 判断问题 |
|------|----------|
| 玩家问题 | 是否解决同一种玩家需求，而不只是题材或界面相似 |
| 重复行为 | 相似的是表面功能，还是玩家长期反复执行的动词链 |
| 产品条件 | 平台、商业模式、社交结构、会话长度和上线阶段是否接近 |
| 制作条件 | 内容量、工具链、团队能力与更新节奏是否可承受 |
| 迁移缺口 | 哪些条件缺失会让该做法失效或产生相反结果 |

热门、同题材或同平台不能自动证明可迁移。“采用 / 变体采用 / 不采用”属于项目取舍，只有达到升级门槛时交 `design-inference`。

## 输出切片

- 调查问题与当前结论。
- 关键事实及来源快照、证据层级和可信度。
- 可比条件、不可比条件与反例。
- 新增、替换或失效来源对既有结论的影响。
- 仍会改变项目选择的未知项。
