# 测试证据、归因与指标解释

用于试玩、用户测试、灰盒验证、问卷、社区反馈、埋点、线上指标或 A/B 结果分析。目标是把“发生了什么”拆成证据、归因和下一步动作。

## 测试方法对照

| 方法 | 主要用途 | 典型证据 | 常见误用 |
|------|----------|----------|----------|
| 一次性测试 | 首次体验、新手引导、第一印象 | 首次停顿、误解、放弃、复述 | 复用同一玩家后还当首次体验 |
| 黑盒测试 | 自然行为、非预期路径、理解偏差 | 路径、假设、无提示行为 | 讲太多规则，污染自然行为 |
| 白盒测试 | 指定功能、边界路径、Bug | 脚本步骤、复现、日志 | 用来判断自然玩家是否理解 |
| 回归测试 | 修改后旧路径是否仍成立 | 旧用例通过 / 失败 | 只测新改动，不测旧路径 |
| 负载测试 | 多人在线、服务稳定性 | 延迟、掉线、吞吐、错误率 | 用小样本人工体验替代压力数据 |
| 线上指标 | 发现异常、趋势和分群差异 | 留存、漏斗、完成率、流失点 | 直接把相关性当原因 |
| A/B 测试 | 比较明确变量的线上效果 | 分组指标、置信区间、分群 | 同时改太多变量，无法归因 |

## 首次体验漏斗

首次体验测试只回答“未玩过当前版本的目标玩家第一次能否理解并进入核心循环”。复用同一玩家后，结果只能作为回归、节奏或流畅度证据，不能证明首次理解。

| 节点 | 观察重点 | 指标 / 证据 | 常见归因 |
|------|----------|-------------|----------|
| 首次目标理解 | 玩家是否知道第一步 | 目标理解用时、首个行为、复述 | 目标 Sign 不足、镜头 / UI 干扰、任务表达弱 |
| 第一次输入 | 玩家是否能执行核心动作 | time-to-first-input、输入错误、停顿 | 输入映射不清、目标太小、反馈不足、设备差异 |
| 第一次成功 | 玩家是否理解做对结果 | time-to-first-success、下一步行为、成功复述 | Feedback 不足、奖励不可见、状态变化不清 |
| 第一次失败 | 玩家是否知道原因并恢复 | 首次失败原因、重试率、恢复用时 | 失败反馈不足、惩罚过重、归因到不公平或 Bug |
| 第一次奖励 | 玩家是否理解奖励价值 | 领取率、使用率、奖励后目标变化 | 奖励用途不明、价值锚点缺失、过早复杂化 |
| 首次核心循环完成 | 玩家是否完成最小闭环 | 完成率、闭环用时、复述正确率 | 目标链断裂、节奏过长、反馈不能指向下一步 |
| 教学退场 | 提示减少后是否能继续 | 提示使用、退场后停滞、独立完成率 | 教学只训练服从脚本，没有建立心智模型 |

## 证据类型

| 类型 | 可说明 | 不可说明 |
|------|--------|----------|
| 行为观察 | 玩家实际做了什么、卡在哪里 | 玩家为什么喜欢或讨厌 |
| 访谈自述 | 玩家解释、动机、感受词 | 真实行为比例 |
| 问卷 | 大样本主观倾向 | 具体失败原因 |
| 录像 / 日志 | 可复查路径、输入、失败点 | 没记录到的动机 |
| 漏斗数据 | 哪一步流失或转化异常 | 异常背后的唯一原因 |
| 社区反馈 | 强情绪和高频争议 | 总体玩家代表性 |

## 归因检查

每个问题至少检查四类原因：

| 归因类别 | 检查问题 | 处理方向 |
|----------|----------|----------|
| 产品问题 | 目标、规则、Sign、Feedback、UI、数值、节奏、输入、目标规格或时间窗口是否导致失败 | 改设计或表现 |
| 测试情境 | 环境、设备、时长、讲解、版本质量是否影响结果 | 调整测试设置并重测 |
| 玩家状态 | 疲劳、分心、经验不足、非目标玩家是否影响结果 | 标注样本限制 |
| 目标玩家不匹配 | 设定的目标玩家是否本来就不会接受该体验 | 回查概念或目标用户 |

不要直接写“用户错误”。至少说明是运动控制错误、流程错误、遗漏错误、错误行动、规则误解、动机不匹配还是测试情境造成。

## 基本归因错误防线

- 设计师看到玩家失败时，先假设产品可能没表达清楚，再看样本和环境。
- 玩家抱怨“不公平”时，先找具体失败点、信息不透明、概率误解、反馈缺失或恢复路径，再判断是否只是情绪表达。
- 测试版本不稳定时，不忽略反馈；把 Bug / 性能和设计问题分栏记录。
- 多个目标玩家重复失败时，不要用“玩家没认真看”解释。
- 单个极端反馈不要直接改核心规则；先找复现证据或下一轮验证题。

## 指标解释规则

- 指标回答“哪里变了”，不自动回答“为什么变了”。
- 留存下降先拆新手漏斗、关键失败点、会话时长、加载 / 崩溃、版本变化、渠道和玩家分群。
- 完成率低不一定说明难度高，也可能是目标不清、奖励不足、路径过长、Bug、输入问题或退出点错误。
- 付费转化高不一定健康；同时看退款、投诉、付费后流失、竞技胜率差和长期经济通胀。
- A/B 只能解释被控制的变量；如果同时改 UI、奖励和难度，结论只能写成复合假设。

## 问题归因表

| 观察 | 证据类型 | 影响范围 | 归因候选 | 证据强度 | 建议动作 | 回归方式 |
|------|----------|----------|----------|----------|----------|----------|
| | 行为 / 自述 / 录像 / 日志 / 指标 | 教程 / 核心循环 / UI / 数值 / 商业化 | 产品 / 情境 / 玩家状态 / 目标不匹配 | 强 / 中 / 弱 | | |

## 迭代动作选择

| 归因 | 首选动作 | 不建议直接做 |
|------|----------|----------------|
| Sign 不足 | 增强目标、可操作性、风险和下一步提示 | 只降难度 |
| Feedback 不足 | 增强即时反馈、结果留存和失败原因 | 只加说明文字 |
| 输入问题 | 调目标尺寸、容错、响应、镜头和控制 | 只补教程 |
| 目标规格问题 | 调目标大小、距离、移动速度、时间窗口、吸附、缓冲输入或反馈 | 直接降奖励或降敌人数值 |
| 数值压力 | 调曲线、资源、失败代价和检查点 | 直接改核心规则 |
| 规则误解 | 改规则表达、教学顺序和低风险练习 | 责怪玩家不读文案 |
| 动机不匹配 | 回查目标玩家、核心情绪和奖励结构 | 堆奖励强行留存 |
| Bug / 性能 | 修复并回归旧路径 | 把异常当成设计偏好 |
