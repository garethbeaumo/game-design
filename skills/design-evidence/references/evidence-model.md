# 统一证据模型

所有模式都使用同一套来源快照、证据层级和可信度口径。它们的作用是限制结论能证明到哪里，不是把短调查扩成档案工程。

## 来源快照

在解释材料前记录能让别人重新定位同一条件的信息：

| 字段 | 内容 |
|------|------|
| 对象与定位 | 游戏 / 功能 / 文件 / URL / 测试批次，以及路径、时间点或原始产物位置 |
| 当前版本 | 版本号、平台、分支与提交、构建、配置版本或实验分组；未知时明确写未知 |
| 采集条件 | 日期、环境、地区、设备、账号状态、样本和干预方式中真正影响结论的部分 |
| 获取方式 | 直接游玩、官方说明、代码读取、运行探针、录像、日志、查询或二手转述 |
| 新鲜度与局限 | 可能过期、无法复现、样本偏差、访问缺口或只覆盖局部路径 |

快照只固定条件并指向原始材料，不复制整份网页、日志或代码。来源发生变化时记录“新增 / 替换 / 失效”，并说明它改变了哪些结论。

## 证据层级

| 层级 | 含义 | 可支持的结论 |
|------|------|----------------|
| L0 来源快照 | 只知道材料来自哪里、处于什么条件 | 可定位材料，尚不能单独证明主张 |
| L1 直接观察 | 在快照条件下可直接看到的行为、字段、数值或结果 | 证明该对象在该条件下发生了什么 |
| L2 交叉印证 | 独立来源、重复样本或不同方法支持同一事实 | 支持更稳定的模式，但仍受版本和样本边界限制 |
| L3 有限推断 | 从 L1 / L2 推导的解释，并列出替代解释和推翻条件 | 支持后续候选判断，不等于项目决策 |

项目选择和正式规则不属于更高一层证据；它们分别交 `design-inference` 和 `design-docs`。

## 可信度

- **强**：来源直接、版本匹配、可复现或多来源一致，关键反例与替代解释已检查。
- **中**：有重复观察，但版本、样本、环境或可比性存在明确限制。
- **弱**：单条反馈、单次异常、二手转述、口头推测或关键条件不明，只能登记待验证假设。

可信度不是来源名气的评分。官方说明可以证明声明过什么，却未必证明实际运行；一次真实运行可以证明该次路径，却不能自动外推到所有玩家和版本。
