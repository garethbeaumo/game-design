# `implementation`：实现事实反推

从代码、序列化资产、配置、构建、运行实例或生产链路提取当前实际行为。目标是界定每项证据真正证明到哪里，不是修复代码或用旧文档替代当前状态。

## 原则

- 优先追踪当前分支、实际引用、激活配置和真实运行路径；历史提交、旧计划和未接线代码只作背景。
- 分开实现事实、设计意图、合理推断、冲突与未知项。当前实现和临时原型默认只是可变基线，不自动成为设计约束。
- 高层证明不能凭名称倒推。健康检查、编译通过或存在配置都不能证明真实客户端完成了目标链路。
- 若目标是审查、调试或修复故障，应退出本 Skill；本模式只在需要可追溯设计证据时使用。

## 实现证明层

这些层是不同证明范围，不保证自动累积。报告必须同时写“证明了什么 / 没有证明什么”。

| 层 | 证据 | 能证明 | 不能自动证明 |
|----|------|--------|--------------|
| I0 静态实现 | 当前代码、引用图、接口、测试源码 | 某条逻辑或候选路径存在 | 已被构建、接线、配置或执行 |
| I1 序列化状态 | Scene、Prefab、资源、Inspector 数据、存档结构 | 某个版本保存了对象、引用或默认值 | 运行时未被覆盖，或目标构建包含它 |
| I2 配置 | 当前配置内容、选择规则、环境变量投影 | 指定环境配置出的输入与路由 | 进程实际加载且产生预期结果 |
| I3 本地运行 | 本地实例、自动测试、加载日志、探针、请求响应 | 指定本地版本和条件下的真实行为 | 目标平台、部署环境或生产链路一致 |
| I4 目标环境 | 目标设备 / 平台构建、测试服或实际部署实例 | 指定目标环境中的行为与集成 | 生产真实流量、账号、依赖和持久化 E2E |
| I5 生产 E2E | 真实客户端经生产入口、服务依赖、状态写入与回读形成闭环 | 该时间点、版本、账号和路径的生产端到端行为 | 所有分支、负载、地区和后续版本都成立 |

## 流程

1. 定义要核对的行为、当前设计基线和需要达到的最高证明层。
2. 建立来源快照：分支与提交、构建、序列化资产、配置版本、环境、进程或部署版本。
3. 沿实际入口追踪对象、触发、状态、事件、输入、反馈、依赖和持久化，不把未接线路径算作当前行为。
4. 在授权范围内做最小安全验证，并记录每层的真实输出；未运行的层明确写“未验证”。
5. 标出实现缺文档、文档缺实现、配置漂移、环境差异和伪约束候选。

离线模拟或数据原型还要记录模型 / 模拟器版本、参数、样本或随机种子、正常与极端输入、原始结果、复现命令或脚本入口及局限；这些属于 implementation 证据，不能改写成玩家试玩结论。

## 输出切片

| 主张 | 证明层 | 来源快照 / 定位 | 复现入口 | 证明了什么 | 未证明什么 | 可信度 |
|------|--------|-----------------|----------|------------|------------|--------|
| | I0-I5 | | | | | 强 / 中 / 弱 |
