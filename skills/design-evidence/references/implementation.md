# `implementation` 模式：实现事实反推

用于从 Unity 场景、脚本、Prefab、配置、原型、历史说明或口头规则中提取当前行为。产物是实现事实报告，不是补写后的正式策划案。

## 权限

- 写入 `FACT-*` / `EVID-*`：来源、实现事实、合理推断、可信度、冲突、伪约束候选和未知项。
- 实现、资源、历史资料和已有策划均作为只读证据。
- 不把当前代码当成正确设计，不创建或确认概念、系统地图、产品 MVP 或功能规则。

## 工作原则

- 明确区分实现事实、合理推断和待确认问题。
- 以读取、定位和总结为主；不要为了取证大范围修改 Unity 资源。
- 当前实现、历史习惯和临时原型默认只是伪约束候选，除非有确认来源。
- 用户同时要求补正式设计时，本模式只增加推荐落点；正式落档另交 `design-docs`。

## 流程

1. 确定要核对的是顶层承诺、系统边界还是具体功能规则。
2. 读取指定实现、相关引用和已有文档；Unity 资源优先通过脚本、配置和引用关系定位，必要时再做编辑器验证。
3. 提取对象、触发、状态、事件、字段、常量、输入、反馈和依赖等可观察事实。
4. 标出实现存在但文档缺失、文档存在但实现缺失、实现之间冲突和伪约束候选。
5. 为每条事实记录来源位置，为每条推断标记高 / 中 / 低可信度及验证路径。
6. 把未确认的设计意图交 `design-inference`，把已确认事实的正式落档交 `design-docs` 对应模式。

## `standard` 输出

- 核对范围、版本和来源。
- `FACT-*` 实现事实及定位。
- 合理推断、可信度和验证路径。
- 与现有设计的差异与冲突。
- 伪约束候选和待确认问题。
- 推荐交接：`design-inference` 或 `design-docs` 的具体模式。

## 自检

- 关键事实能否定位到文件、对象、配置、场景或可复现行为。
- 是否把事实、推断和设计意图分开。
- 是否避免用当前实现覆盖已确认设计。
- 是否没有代写正式设计正文。
