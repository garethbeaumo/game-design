# `playtest`：试玩与指标归因

分析试玩、访谈、问卷、社区反馈、录像、日志、线上指标或 A/B 结果，说明在什么条件下发生了什么、证据多强和还需验证什么。

## 原则

- 用 `./evidence-model.md` 固定构建、规则版本、环境、样本、分组、埋点和干预方式。
- 反馈不是结论；分开行为、自述、情绪、用时、路径、失败点、日志与指标。
- 小样本可以发现问题，不能证明比例；相关性可以发现变化，不能自动解释原因。
- 首次体验结论需要未玩过当前版本的目标玩家提供直接证据；若只有复用玩家，结论只覆盖回归、节奏、流畅度或已知路径，不能外推为首次体验。
- Bug、性能、测试污染、样本偏差和设计问题分别记录。

## 按材料补充检查

只读取并填写与本次材料相符的一行，不把所有调查都扩成实验报告：

| 材料 | 额外需要固定的条件 |
|------|--------------------|
| 试玩 / 录像 / 访谈 | 招募条件、是否首次接触、任务脚本、主持干预，以及行为与自述是否一致 |
| 社区 / 客服 / 问卷 | 采样入口、重复用户、主动发声偏差、问题措辞和可代表范围 |
| 日志 / 遥测 / 指标 | 事件定义、分母、时间窗、缺失与重复、版本暴露和数据完整性 |
| A/B 或受控实验 | 分流单位与均衡、样本和暴露窗口、效应与不确定性、护栏指标、停止规则、污染与新奇效应 |

## 归因步骤

1. 记录测试问题、方法、版本、环境、样本，以及材料类型命中的分组、时间窗、护栏和停止条件。
2. 提取 L1 直接观察并保留反例，不把“没做”直接写成“不喜欢”。
3. 检查行为、自述和指标是否互相印证，形成 L2 模式或标出冲突。
4. 对每个 L3 归因列出替代解释、可信度和会推翻它的条件。
5. 下一轮验证尽量只改变一个关键变量；达到当前决策所需证据后停止扩样。

## 输出切片

- 测试问题、来源快照和样本限制。
- 可复查观察、关键反例和证据层级。
- 归因假设、可信度、替代解释和混杂因素。
- 相比上一轮新增、替换或失效的证据。
- 需复查、重测或继续观察的事项。

报告可以提出验证方向；项目是否改、改哪一种方案属于 `design-inference`，未达到其升级门槛时直接在当前设计变更中内联判断。
