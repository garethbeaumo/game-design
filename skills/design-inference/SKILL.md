# 游戏设计推论

为一次高影响设计变化收束真实候选、关键取舍、验证信号和回退条件。默认工作单位是当前变更中的决策切片，不是完整策划案，也不为普通判断创建独立决策档案。

## 启用门槛

先确认存在一个会改变行动的决策问题。满足以下任一升级条件才使用本 Skill：

- 至少两个真实可行候选（可包含“保持当前基线”），选择会显著改变玩家体验、产品范围或长期成本。
- 变更跨越多个 `SYS-*`、接口或内容管线，选错后迁移、返工或回退代价高。
- 成形方案存在高影响争议，需要明确反选代价、责任边界或可审计结论。
- 一个致命假设会推翻选择，且只能通过最小 Prototype 获得足够证据。

若选择低成本、可逆、影响局部，或只有一个明显可行方案，直接在当前设计变更中内联“判断 / 依据 / 验证 / 回退”，不进入本 Skill，也不虚构候选来填表。

## 边界

- 输入可来自来源快照、现有 `EVID-*`、用户确认、当前设计或明确假设；正式 `EVID-*` 不是推理前置门槛。
- 可比较候选、形成推荐、设计 Prototype，或在达到归档门槛时创建 `DEC-*`。
- 不替专项调查解释未经整理的大量原始材料，也不直接改写概念、`SYS-*`、产品范围或 `RULE-*`。
- 评审只指出会改变选择的高影响问题；普通问题直接反馈给当前变更，不升级成决策工程。

## 记录粒度

- **内联决策切片（默认）**：问题、选择、关键依据、影响、验证信号和回退条件。
- **独立 `DEC-*`**：只有决定理由需要脱离当前 change-set 单独维护时才创建，例如会被多个后续产物长期引用、需要正式审批 / 审计，或同一争议会跨轮次复查。高影响或跨系统本身不自动要求独立记录，明确要求某种格式也不会越过门槛。
- **Prototype 计划**：仅在致命假设阻塞选择且没有更便宜证据时创建；已完成原型的参数与结果属于证据，不写进 `DEC-*` 代替证据包，随后再把有限结论带回决定。

## 流程

1. 通过启用门槛，描述当前基线、要改变的范围、必须决定的问题和本次不回答的内容。
2. 区分硬约束、软约束、伪约束、证据和必要假设。
3. 形成真正不同的候选；没有真实差异时停止比较，不制造形式上的 A / B。
4. 只选择会改变本次选择的决策镜头，比较玩家价值、跨系统影响、可逆性、证据强度、验证与返工成本。
5. 给出推荐、放弃项、反选代价、验证信号和失败回退。
6. 致命假设无法由现有证据判断时，设计最小 Prototype；否则避免扩大验证范围。用户要求记录已完成的参数、边界和结果，或结果需长期引用 / 独立复查时，模拟、代码、配置和运行结果明确交 `design-evidence:implementation`，玩家行为与访谈交 `design-evidence:playtest`；低风险直接结果才在当前决策切片内记录来源与局限。`DEC-*` 只引用证据结论，不能替代证据记录。
7. 选择内联决策切片或必要的 `DEC-*`；确认后的游戏规则交 `design-docs` 差量落档；若取舍由活跃版本 change-set 发起并改变范围、优先级、迁移或发布判断，则把决定交回 `design-workflow`，不经由 `design-docs` 代管版本事实。

## 完成标准

- 决策已通过升级门槛；候选有真实差异，或硬约束淘汰后只剩唯一可行项且淘汰依据可追溯。
- 比较只使用改变选择的镜头，没有把整个策划案重新评审一遍。
- 推荐包含反选代价、验证信号和回退条件，依据强弱与未知项可见。
- Prototype 结果能回到被阻塞决定；复现字段与证据类型匹配，需独立记录的离线模拟明确归入 `design-evidence:implementation`，没有被写成玩家试玩或塞进 `DEC-*` 代替证据。
- 普通判断没有被膨胀成 `DEC-*`，Prototype 没有膨胀成产品版本，结论没有越权成为当前规则。
