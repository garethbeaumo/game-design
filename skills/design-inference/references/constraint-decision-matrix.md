# 约束与候选比较

先判断一次取舍是否值得独立推论。影响局部、可快速回退且没有真实候选时，直接在当前变更中内联判断。

## 升级检查

| 问题 | 升级信号 |
|------|----------|
| 玩家与范围 | 会显著改变核心行为、目标玩家承诺、版本范围或长期经济 |
| 跨系统 | 同时改变多个 `SYS-*`、接口、内容管线或数据所有权 |
| 可逆性 | 上线后需要迁移存档、重做大量内容、重训玩家或承担高回退成本 |
| 争议与审计 | 多方结论冲突，或决定需要长期引用、责任边界和复查依据 |

## 约束分类

| 类型 | 含义 | 处理 |
|------|------|------|
| 硬约束 | 明确平台、法规、合同、预算上限或已确认上层承诺 | 候选必须满足；记录来源和适用期限 |
| 软约束 | 成本、习惯、偏好或可协商目标 | 比较收益、代价和可逆性 |
| 伪约束 | 当前实现、历史做法、竞品惯例或无来源口头说法 | 标为假设，不因“已经这样”自动淘汰候选 |
| 未知项 | 会改变选择但尚无答案 | 给默认、最小验证、延后点或明确阻塞 |

## 候选质量

- “保持当前基线”可以是候选，但必须写清不改变的代价。
- 候选要在玩家行为、规则结构、范围或风险分配上有实质差异；只改参数不算新的方向。
- 不为凑数量虚构弱候选。只有一个方案满足硬约束时，说明淘汰依据并结束比较。

只保留会改变选择的比较维度：

```markdown
| 候选 | 玩家结果 | 关键依据 / 假设 | 跨系统影响 | 可逆性 / 返工 | 最小验证 | 失败回退 |
|------|----------|-----------------|------------|---------------|----------|----------|
| 保持基线 / A | | | | | | |
| B | | | | | | |
```

实现成本可以改变验证方式、范围和时机，但不能自动替代玩家价值判断；同样，理想体验也不能抹去明确的迁移与维护代价。
