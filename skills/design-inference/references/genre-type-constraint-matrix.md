# 品类与游戏类型约束矩阵

用于 Phase 1 显性约束澄清。目标是先确认“玩家核心乐趣来自哪里”和“产品形态如何影响时间、付费、留存与流失”，再推导后续设计边界。

本参考只给设计判断题，不替代外部证据。涉及具体市场表现、体量锚点或可比做法时，使用 `design-evidence` 的 `competitor` 模式调查已上线游戏。

## 使用顺序

1. 确认品类：玩家主要追求的核心乐趣是什么。
2. 确认游戏类型：手游 F2P、单机买断、端游 / 网游、小游戏、买断 + 长线服务、订阅或混合。
3. 交叉推导派生约束：驱动力可行性、循环节奏、流失关注点和设计优先级。
4. 把结论写入本次推论或 `DEC-*`；确认后再交 `design-docs` 的对应模式落档。

## 品类判断题

| 品类 | 核心乐趣 | 必问问题 | 常见偏离 |
|------|----------|----------|----------|
| SLG | 战略博弈、积累感、社交对抗 | PVP 是“打得过”还是“打得爽”？决策周期是天、小时还是分钟？ | 把长期战略做成短期数值碾压 |
| 卡牌 / 收集 | 收集、养成、组合策略 | 价值来自稀有度、构筑组合还是角色情感？期待感来自未知还是保底确定性？ | 只有抽取，没有构筑或表达 |
| 模拟经营 | 资源循环、成长可见、优化满足 | 满足感来自建成结果还是建造过程？离线收益是补偿还是必要主循环？ | 资源循环断头，只剩等待 |
| 放置挂机 | 成长感知、低门槛、高频正反馈 | 玩家是在主动玩，还是在查看收益？回归时是“赚了很多”还是“错过很多”？ | 用惩罚制造回归压力 |
| 休闲 / 益智 | 即时满足、碎片时间、轻负担复玩 | 玩家能否低注意力游玩？失败后是“再来一次”还是“算了”？ | 信息量、操作和惩罚超出碎片场景 |
| RPG | 角色代入、叙事推进、成长选择 | 玩家更关心角色变强、故事推进还是队伍关系？战斗服务叙事，还是叙事包装战斗？ | 成长、叙事和战斗互相抢主轴 |
| Roguelike / 肉鸽 | 随机重玩、风险博弈、构筑发现 | 死亡后玩家觉得“我知道哪错了”还是“运气不好”？构筑是在选路径还是只选强度？ | 随机性遮蔽学习，构筑只有数值强弱 |
| 解谜 | 顿悟快感、逻辑推演、认知挑战 | 卡关时玩家觉得“我没想到”还是“这不合理”？解法唯一还是多路径？ | 规则不透明，把误导当难度 |
| 三消 | 即时反馈、连锁爽感、目标驱动 | 目标是过关、高分连击还是收集推进？难度来自棋盘结构、步数限制还是道具消耗？ | 爽感被门槛和付费压力盖过 |
| 沙盒 | 自由表达、涌现玩法、自定目标 | 游戏给玩家任务、工具还是规则材料？高光由设计者安排还是玩家创造？ | 自由没有重新定向，玩家迷路 |
| 国战 / 大规模阵营 | 阵营归属、集体博弈、权力争夺 | 个人行为对全局是否有可见影响？落后阵营能否翻盘？ | 强者滚雪球，弱势玩家无意义参与 |

## 游戏类型约束

| 游戏类型 | 时间投入模式 | 付费 / 价值预期 | 主要流失风险 | 设计含义 |
|----------|--------------|----------------|--------------|----------|
| 手游 F2P | 高频短会话、长期留存 | 免费路径清楚，付费换效率、外观或概率 | 前期不懂、中期卡点、后期疲劳或不公平 | 进度、奖励、付费透明度和运营节奏必须一致 |
| 单机买断 | 集中体验、完成率或口碑 | 一次购买，期待完整体验 | 上手慢、内容不足、结局前疲劳 | 优先保证节奏、完成体验和可推荐高光 |
| 端游 / 网游 | 长会话、社交关系和长期目标 | 时间投入、社交身份、外观或服务 | 社交压力、数值膨胀、老玩家壁垒 | 社交密度、成长追赶和公平感是硬约束 |
| 超休闲 / 小游戏 | 极短会话、低学习成本 | 广告、轻付费或传播 | 第一局不懂、失败不想重试 | 输入、反馈、失败恢复必须极轻 |
| 买断 + 长线服务 | 首发完整体验 + 后续内容 | 本体价值可信，追加内容有清楚边界 | 首发内容不足或长线承诺过重 | 首发闭环和扩展边界都要明确 |
| 订阅 / 会员型 | 稳定回访、内容库或持续服务 | 持续价值感和更新节奏 | 内容消耗、价值感下降 | 内容节奏、复用和更新可持续性优先 |

## 交叉推导

确认品类和游戏类型后，至少推导四个派生约束：

| 派生约束 | 推导问题 | 输出 |
|----------|----------|------|
| 驱动力可行性 | 品类需要什么驱动力？产品类型能支持什么驱动力？ | 主驱动力、副驱动力、不可行驱动力 |
| 循环节奏 | 品类自然循环长度与单次时长是否匹配？ | 短循环 / 中循环 / 长循环目标时长和压缩方式 |
| 流失关注点 | 品类常见流失点与产品类型流失节奏在哪里相交？ | 流失触发、观察指标、干预时机 |
| 体验取舍 | 核心乐趣与商业 / 内容 / 平台约束冲突时先保什么？ | 必须保留、可延后、明确不做 |

## 质量检查

- 是否把品类当成核心乐趣边界，而不是市场标签。
- 是否把游戏类型当成时间、付费、留存和流失约束，而不是发行渠道名称。
- 是否说明品类和类型冲突时要调整哪个，而不是继续堆系统。
- 是否推导了驱动力、循环节奏、流失关注点和设计优先级。
- 是否把结论交给正确的 `design-docs` 模式或 Prototype 计划，而不是在本参考中展开下游专项。
