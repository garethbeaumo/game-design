# Prototype 验证计划

用于设计验证致命假设的最小 Prototype。`design-inference` 只拥有验证问题、原型范围、通过标准和失败回退；原型执行后的录像、日志、样本、观察、归因与证据强度统一交 `design-evidence:playtest`。

## 原型类型

| 类型 | 适用问题 | 不适用 |
|------|----------|--------|
| 纸面原型 | 卡牌、桌面规则、早期流程和选择结构 | 手感、时间窗口、镜头或物理反馈 |
| 灰盒数字原型 | 核心动作、控制、移动、战斗和反馈节奏 | 视觉吸引力或最终内容量 |
| 可交互 Demo | 完整短循环、节奏与玩家理解 | 长线内容和完整产品范围 |
| 表格推演 | 定性资源流、成长假设与成本收益 | 玩家操作理解和情绪反应 |
| 白盒脚本 | 指定功能、边界路径与回归前提 | 自然行为和首次体验 |

## 计划字段

| 字段 | 要求 |
|------|------|
| 致命假设 | 不验证就无法继续作决定的判断 |
| 原型范围 | 只包含足以暴露该假设的交互，不等于产品 MVP |
| 目标样本 | 需要哪类玩家或环境，为什么 |
| 观察证据 | 预先说明要记录的行为、用时、失败点、复述或路径 |
| 通过 / 失败标准 | 可观察且在执行前写定 |
| 失败回退 | 回到哪个候选、约束或决策节点 |
| 证据交接 | 执行材料将由哪个 `TEST-*` / `EVID-*` 承接 |

## 输出片段

```markdown
## Prototype 计划
- 致命假设：
- 不验证的后果：
- 原型类型：
- 包含：
- 不包含：
- 目标样本与环境：

| 观察证据 | 通过标准 | 失败标准 | 失败回退 |
|----------|----------|----------|----------|
| | | | |

## 执行交接
- 原始录像 / 日志 / 访谈 / 指标位置：
- 计划创建的 `TEST-*` / `EVID-*`：
- 执行后返回的决策问题：
```

禁止在本产物中填写实际观察、样本结论或问题归因。执行完成后先由 `design-evidence:playtest` 固化证据，再返回 `design-inference` 判断是否维持、修订或回退决定。
