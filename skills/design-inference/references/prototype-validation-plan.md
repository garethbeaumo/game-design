# Prototype 验证计划

只有一个未知项会推翻高影响选择，且现有证据与更便宜的纸面检查都无法回答时，才设计 Prototype。它是一次有停止条件的决策实验，不是产品 MVP、功能纵切或完整工程版本。

## 选择最小媒介

- 纸面或规则原型：选择结构、信息与收益关系。
- 灰盒或交互原型：控制、节奏、空间与反馈。
- 数据或模拟原型：数值关系、产出、极端情况与稳定性。
- 内容样片：单个内容结构、表现方向或制作成本。

## 必要字段

| 字段 | 要求 |
|------|------|
| 被阻塞的决定 | 哪个候选选择因该未知项无法继续 |
| 致命假设 | 失败为何会推翻候选，而不只是让它稍微变差 |
| 当前基线 | 对照什么，不能只测一个没有比较对象的方案 |
| 包含 / 不包含 | 只保留暴露假设所需的规则、内容和技术 |
| 来源快照 | 原型及模型 / 模拟器版本、参数、样本或随机种子、环境和测试方式 |
| 边界输入 | 正常区间、极端情况、无效输入及本轮没有覆盖的组合 |
| 观察证据 | 原始结果、行为、用时、失败、路径、复述或指标 |
| 复现入口与局限 | 命令、脚本、配置或操作步骤，以及不能由本次结果推出什么 |
| 通过 / 失败 / 停止 | 执行前写定、可观察，避免边测边改成功标准 |
| 失败回退 | 返回哪个候选、约束或决策节点 |

先验证最致命且最便宜的问题；同一轮尽量只改变一个关键变量。实现原型属于相应技术任务。用户要求记录已完成的参数、边界和结果，或结果需要专项复查 / 长期引用时，玩家行为、访谈和体验指标交 `design-evidence:playtest`，代码、配置、模拟与运行结果明确交 `design-evidence:implementation`；直接且低风险的结果才在当前决策切片内记录来源与局限。`DEC-*` 可引用有限结论，但不能替代参数、原始结果和复现入口。随后返回本 Skill 维持、修订或回退决定。
