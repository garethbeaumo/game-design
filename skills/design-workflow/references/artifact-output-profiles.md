# 策划交付深度

深度只决定本次回答或改动展开多少，不决定路由、成熟度或项目范围。

| 深度 | 适用场景 | 最小交付 |
|------|----------|----------|
| `brief` | 咨询、小型差量、单一判断 | 变化、依据、影响、未知、下一步 |
| `standard` | 新增或修订一个可持久化设计切片 | 当前基线、差量、状态、验收、复查或回退 |
| `implementation-ready` | 已明确交实现的功能规则 | 在 `standard` 上补数据语义、状态/事件、资源影响、兼容性和可执行验收 |

完整设计包、跨系统范围和版本快照不是“更深”的单篇产物，由 `design-workflow` 按需编排。

## 原则

- 默认修改最小受影响范围；一次 change-set 可以同步系统注册表和一篇功能规则，不为形式强拆多份文档。
- 现有权威优先差量修订；未命中字段直接省略。
- 草案、当前、已替代等成熟度由产物状态表达，不混入交付深度。
- `EVID-*`、`DEC-*` 只在需要复现 / 审计、多次外部引用、正式审批或跨轮次复查时提升为独立产物。
- 稳定 `SYS-*` / `RULE-*` 不受上述独立建档门槛限制；只要代码、配置、测试、遥测、任务或多个维护文档需要跨边界引用，就沿用或分配稳定 ID，不必因此新建独立文件。
