# 迭代设计产物标准

默认治理对象是一次 change-set，而不是预先完成整套 GDD。目录沿用项目现有结构，不强制创建通用编号目录。

## 当前基线与 change-set

- 策划权威载体可以同时承载 `proposed`、`current` 与 `superseded`；“当前设计基线”只指其中 `current` 的可执行视图，草案和实验不会因同处一份权威文档而自动生效。
- change-set 可以直接对应现有需求、PR 或一次文档差量，不要求另建 Change Request 文件。
- 最少记录：变更原因、受影响范围、当前状态、可观察验收、复查或回退条件。
- 一次 change-set 可以新增、修改、拆分、合并或废弃系统与规则，并列出必要的下游同步。

## 两个状态维度

| 维度 | 状态 | 含义 |
|------|------|------|
| 当前性 | `proposed` | 提案或实验，尚未成为当前基线 |
| 当前性 | `current` | 当前版本采用的设计 |
| 当前性 | `superseded` | 已被替代，保留替代关系 |
| 验证性 | `unverified` | 尚无足够验证，只能作为待验证默认 |
| 验证性 | `supported` | 有与结论范围相称的证据支持 |
| 验证性 | `rejected` | 证据已否定该假设，或命中预先写定的失败条件 |

状态属于具体变更、系统或规则；不要因为整篇文档某一处未验证，就把所有内容降成同一状态。尚未采用的提案被改写或放弃时，原位更新或移除，由版本历史追溯；它从未是 `current`，不能误标为 `superseded`，没有失败证据时也不能误标为 `rejected`。确需长期比较的多个高影响候选属于决策记录，不是并列的当前设计权威。

## 事实所有者与稳定引用

| 范围 | 当前权威 |
|------|----------|
| 外部、试玩和实现事实 | `design-evidence` 报告或原始来源 |
| Prototype 的参数、原始结果、复现入口与证明边界 | `design-evidence` 报告或原始来源 |
| 高影响取舍及基于 Prototype 证据形成的有限决策结论 | `design-inference` 的决策记录（仅按需） |
| 当前概念、系统注册表和功能规则 | `design-docs` 对应文档 |
| 版本范围、里程碑、负责人和发布判断 | `design-workflow` |

- `SYS-*` 以及被代码、配置、测试、遥测、任务或多个维护文档等真实外部消费者引用的规则保留稳定 ID。
- 普通段落、短期实验和一次性观察不强制编号；Git 历史足以追溯时不另造产物。
- 索引、快照和交接表只引用当前权威，不能复制成另一份可独立修改的规则。

## 提升为独立产物的门槛

独立文件需要有自己的生命周期，不能只因为内容重要或跨系统就创建：

| 产物 | 提升门槛 |
|------|----------|
| `EVID-*` | 需要他人复现 / 审计、多次引用，来源存在实质冲突，或用户明确要一份独立证据交付 |
| `DEC-*` | 决定理由会被多个后续产物长期引用，需要正式审批 / 审计，或同一争议会跨轮次复查 |
| 治理记录 | 版本、负责人、审批、迁移窗口或发布出口需要跨项协调，且现有需求 / PR 无法承载 |

高影响、跨系统和高返工只决定检查强度；若当前 change-set、权威文档或现有任务已经能承载，就保持内联。

## 替代、归档与版本

- 记录目标版本或里程碑；同一系统在不同版本可以有不同状态。
- 被替代内容写明 `superseded_by` 或替代原因，并从当前导航降级。
- 实现与设计不一致时，先判断是实现偏离还是团队接受新行为；代码和旧文档都不能自动覆盖当前权威。
