# 风险驱动的就绪检查

本文件回答“这个 change-set 是否足以进入下一项具体行动”。检查可跳过、可回环，不构成全项目线性阶段。

## 判断状态

| 状态 | 含义 |
|------|------|
| 通过 | 当前行动所需证据充分 |
| 有条件通过 | 无阻塞项，但有限制、负责人和关闭条件 |
| 未通过 | 已有证据表明不能推进 |
| 未证明 | 关键证据缺失或不可复查 |
| 不适用 | 已说明为何不属于本次影响范围 |

默认只报告阻塞、限制和未证明项，不为模板完整输出全量矩阵。

## 按影响选择检查

| 变化 | 必需检查 |
|------|----------|
| 只改局部规则 | 当前行为差量、失败/恢复、验收和回退 |
| 新增、拆分、合并或废弃系统 | 系统职责、接口、所有者、依赖与迁移 |
| 改变目标玩家、体验承诺或核心循环 | 概念影响、替代关系和受影响下游 |
| 事实不清或实现/文档冲突 | 证据范围、来源层级、未知项和接受哪一侧的决定 |
| 存在高影响真实候选 | 取舍、反选代价、验证信号和失败回退 |
| 跨系统、多人或版本发布 | 关键路径、负责人、兼容性、回归与发布回退 |

## 实现就绪

- 目标行为和本次不改内容清楚。
- 受影响系统、状态/事件、数据语义和资源类型可定位；未命中项可明确不适用。
- 关键假设标为 `unverified`，并有最晚复查时机。
- 验收覆盖正常、边界、失败和恢复；失败有回退或继续迭代入口。

实现就绪不要求整款游戏的概念、系统全集或长期 MVP 已完成。

## 验证就绪

- 假设、目标样本/环境、可观察信号和通过/失败标准在执行前写清。
- 能区分设计问题、Bug、性能、测试污染与样本偏差。
- 只收集能改变当前选择的证据；结果回到当前 change-set，而不是自动升级成全局结论。

## 合入当前设计

- 变更结果有与影响范围相称的证据或明确授权。
- 受影响权威已差量更新，提案/实验不会与 `current` 基线并存而无状态说明。
- 必要的系统注册表、功能规则、测试和实现交接已同步。
- 被替代内容、兼容窗口和失败回退可定位。

## 版本或发布就绪

- 当前版本纳入的 change-set、明确延后项和不做项可定位。
- 跨系统依赖、关键路径、负责人和审批者明确。
- 目标环境回归、存档/协议兼容、监控或人工检查与风险相称。
- 回滚范围、触发信号和沟通对象明确。
