# 团队协作与决策治理

用于共享愿景、创意冲突、跨工种交接、负责人 / 审批者 / 咨询者 / 通知者、沟通节奏和决策记录。

## 使用原则

- 共享愿景必须能作为取舍标准：玩家是谁、核心体验是什么、当前阶段要证明什么。
- 每个阶段只有一个最终决策权入口；多人提供证据，但不能隐藏多个否决权。
- 创意冲突先判断属于事实、方案、正式设计还是制作治理，再回到对应 Skill。
- 事实更新、任务状态和开放问题优先异步记录，会议只解决需要同步判断的问题。
- 高影响决策保留假设、证据、放弃项、影响范围、验证信号与回退条件。

## 决策角色

| 角色 | 职责 | 常见问题 |
|------|------|----------|
| 负责人 | 推动产物完成，维护状态与开放问题 | 有负责人但无决策权 |
| 最终审批者 | 对取舍结果负责，能结束争论 | 多人都能否决但没人拍板 |
| 被咨询者 | 提供专业限制、成本、风险和替代方案 | 过晚咨询导致返工 |
| 被通知者 | 接收已确认变化和同步任务 | 通知缺失导致继续使用旧内容 |

## 冲突分类与路由

| 冲突类型 | 表现 | 推荐处理 |
|----------|------|----------|
| 事实冲突 | 不同来源对竞品、测试或实现描述不一致 | `design-evidence` 对应模式补证据和可信度 |
| 愿景 / 方案冲突 | 对核心体验、循环或机制方向理解不同 | `design-inference` 比较方案；阻塞选择用 `grill-me` |
| 正式设计冲突 | 已确认概念、系统边界或功能规则互相矛盾 | `design-docs` 选择拥有冲突字段的最高层模式修订 |
| 范围冲突 | 每个方案都想进入当前产品或版本 | 产品范围交 `design-docs:system`，制作阶段交 `design-workflow` |
| 制作冲突 | 工种节奏、关键路径或资源管线阻塞 | `design-workflow` 更新里程碑和风险登记 |
| 口味冲突 | 争论只有偏好，没有目标玩家证据或可定位的阶段证据索引 | `design-evidence` 补证据，或 `design-inference` 明确假设与 Prototype |

## 协作字段

| 字段 | 要求 |
|------|------|
| shared_vision_source | 已确认概念、设计支柱或阶段目标 |
| decision_owner | 最终拍板人或角色 |
| consulted_disciplines | 需要提前咨询的实现、内容、表现、音频、测试或制作角色 |
| approval_gate | 哪个状态或阶段门槛通过后才能进入下游 |
| communication_cadence | 日会、周审、里程碑同步或异步文档更新 |
| escalation_trigger | 争议轮次、阻塞时长或受影响门槛 |
| decision_log | 日期、决策、假设、依据、放弃项、影响、验证信号与回退条件 |

## 反模式

- 用“大家都同意”代替明确审批者。
- 没有共享愿景，各工种只按局部目标优化。
- 关键方案只在会议里说过，没有进入 `DEC-*` 或正式权威源。
- 决策记录只有结论，没有假设、证据、验证信号或回退条件。
- 反复讨论同一冲突，却没有新增证据、原型或取舍标准。
- 试图用新增人力解决固有关键路径、沟通成本或方向不清。
