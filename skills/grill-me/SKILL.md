# Grill Me

对计划或设计做穷尽式追问，直到关键分支达成共享理解。

## 工作原则

- 默认使用中文。
- 沿决策树逐分支推进；一次只处理一个阻塞问题。
- 每个问题先给推荐答案和理由，再请用户确认、修正或选择替代项。
- 能靠代码库、场景、Prefab、配置或已有权威文档回答的，先自己查，不拿已知事实拷问用户。
- 不产出完整策划案正文；澄清完成后回到原 skill 继续写文档。
- 用户明确要求跳过追问时停止，并把采用的推荐默认标为待验证。

## 执行流程

1. 识别当前决策树：哪些分支会改变核心体验、范围、依赖、商业化或玩家信任。
2. 按依赖顺序提问：先问约束上层，再问下层取舍。
3. 对每个问题给出：推荐答案、主要理由、反选代价、若仍不确定时的最小验证。
4. 用户修正后，更新后续分支，不要假装旧假设仍然成立。
5. 阻塞分支全部确认或显式默认后，输出简短确认摘要，交回原 skill。

## 完成标准

- 阻塞分支都有明确选择，或有带验证时机的显式默认假设。
- 能复述每个关键选择：选了什么、为什么、反选代价是什么。
- 原 skill 可以在不再猜测关键前提的情况下继续。
